1. CHAPTER 11 전체 개요

순차회로(sequential circuit)는 현재 입력뿐 아니라 과거 입력과 회로에 저장된 현재 상태에 의해 출력이 결정되는 회로이다. 따라서 조합회로와 달리 과거 정보를 기억하기 위한 저장소자가 필요하며, 대표 저장소자가 latch(래치)와 flip-flop(플립플롭)이다.

Latch

클록/enable의 레벨에 반응하는 저장소자

Flip-Flop

클록의 상승 또는 하강 에지에서 상태 갱신

Counter

클록마다 값을 증가/감소시키는 상태기계

Shift Register

클록마다 저장 데이터를 한 비트씩 이동

LFSR

귀환 XOR/XNOR로 의사난수 비트열 생성

FSM

상태 레지스터 + 다음 상태 로직 + 출력 로직

Clock 중심으로 읽는 법
순차회로는 “이 값이 무엇인가?”보다 먼저 “언제 이 값이 바뀌는가?”를 확인해야 한다. posedge, negedge, enable, reset이 상태 갱신 시점을 결정한다.

1.1 동기식과 비동기식

구분동작 원리특징
동기식 순차회로공통 clock에 맞춰 상태 갱신설계·검증이 명확하고 일반적인 디지털 시스템의 기본 구조
비동기식 순차회로각 저장소자가 서로 다른 시점 또는 사건에 의해 변화전파지연과 상태변화 순서에 더 민감

이 장에서 대부분의 디지털 시스템 설계에 사용되는 동기식 순차회로를 중심으로 설명한다.

2.2 11.1.1 Positive D Latch

positive D latch는 clock=1인 동안 입력 din이 출력 qout으로 전달되고, clock=0인 동안에는 이전 qout 값을 유지한다. 11-1은 이 투명(transparent) 구간과 유지 구간을 파형으로 보여준다.

din →
D Latch
clock=1일 때 투명
→ qout

코드 11-1 — Positive D Latch

module dlatch_pos (
    input  clock,
    input  din,
    output qout
);

reg qout;

always @(clock or din) begin
    if (clock)
        qout = din;
end

endmodule
else가 없는 이유
clock=0일 때 새로운 값을 할당하지 않아야 이전 qout을 유지한다. 이 “값 유지”가 바로 latch의 저장 기능이다.

코드 11-2 — 테스트벤치

module tb_dlatch;

reg clock, din;

dlatch_pos U0 (
    clock,
    din,
    qout
);

initial begin
    clock = 1'b0;
    forever #10 clock = ~clock;
end

initial begin
    din = 1'b0;

    #15 din = 1'b1;
    #10 din = 1'b0;
    #10 din = 1'b1;
    #10 din = 1'b0;
    #20 din = 1'b1;
    #10 din = 1'b0;

    #20 $finish;
end

endmodule

3. 11.1.2 D 플립플롭

D Flip-Flop(DFF)은 clock의 천이 에지에서만 입력을 샘플링하고, 다음 유효 에지까지 그 값을 유지한다. 따라서 동기식 디지털 시스템의 기본 저장소자로 사용된다.

din →
DFF
posedge clk
→ qout
감지신호목록
일반적인 edge-triggered DFF는 always @(posedge clk)처럼 clock만 감지한다. 비동기 reset/set이 있다면 해당 reset/set edge도 함께 넣는다.

3.1 코드 11-9 — 상승에지 DFF

module dff_pos (
    input  clk,
    input  din,
    output qout
);

reg qout;

always @(posedge clk)
    qout <= din;

endmodule
posedge clk → din 샘플링 → qout Register 저장 → 다음 posedge까지 유지

3.2 코드 11-10 — 테스트벤치

module tb_dff;

reg clk, din;

dff_pos U0 (
    clk,
    din,
    qout
);

initial begin
    clk = 1'b0;
    forever #10 clk = ~clk;
end

initial begin
    din = 1'b0;

    #15 din = 1'b1;
    #10 din = 1'b0;
    #10 din = 1'b1;
    #10 din = 1'b0;
    #20 din = 1'b1;
    #10 din = 1'b0;

    #20 $finish;
end

endmodule

코드 11-11은 qout과 qout_bar를 모두 sequential block에서 만드는 경우와, qout만 register로 만들고 qout_bar를 조합논리로 만드는 경우를 비교한다.

코드 11-11(a) — 두 출력 모두 nonblocking

module dff_Bad1 (
    input  clk,
    input  din,
    output qout,
    output qout_bar
);

reg qout, qout_bar;

always @(posedge clk) begin
    qout     <= din;
    qout_bar <= ~din;
end

endmodule

코드 11-11(b) — 두 출력 모두 blocking

module dff_Bad2 (
    input  clk,
    input  din,
    output qout,
    output qout_bar
);

reg qout, qout_bar;

always @(posedge clk) begin
    qout     = din;
    qout_bar = ~din;
end

endmodule

코드 11-11(c) — qout만 register, qout_bar는 조합논리

module dff_Good (
    input  clk,
    input  din,
    output qout,
    output qout_bar
);

reg qout;

assign qout_bar = ~qout;

    qout <= din;

endmodule
모델합성되는 저장소자의미
11-11(a)qout용 FF + qout_bar용 FF1비트 저장에 FF 2개 사용
11-11(b)마찬가지로 FF 2개clocked always의 좌변 reg는 저장소자로 추론
11-11(c)qout용 FF 1개 + 인버터가장 자연스러운 구조

module dff_sync_ALrst (
    input  clk,
    input  din,
    input  rstn,

reg qout;

always @(posedge clk) begin

5. 11.2 순차회로에서 Blocking과 Nonblocking

이 장에서 가장 중요한 핵심 중 하나는 순차회로의 상태를 표현할 때 blocking(=)과 nonblocking(<=)의 의미가 다르다는 점이다.

5.1 래치 회로에서의 차이 — 코드 11-5 / 11-6

Blocking

module dlatch_blocking (
    input  en,
    input  a,
    input  b,
    input  c,
    output y_out
);

reg m, y_out;

always @(en, a, b, c) begin
    if (en) begin
        m     = ~(a | b);
        y_out = ~(m & c);
    end
end

endmodule
m = ~(a|b) → 즉시 m 갱신 y_out = ~(새 m & c)

합성 결과에서는 m은 조합논리 결과가 되고, y_out만 latch가 된다.

Nonblocking

module dlatch_Nonblocking (
    input  en,
    input  a,
    input  b,
    input  c,
    output y_out
);

reg m, y_out;

always @(en, a, b, c) begin
    if (en) begin
        m     <= ~(a | b);
        y_out <= ~(m & c);
    end
end

endmodule
우변 m 평가 → 이전 m 사용 → m과 y_out 모두 상태 유지 필요 → Latch 2개

5.2 플립플롭 회로에서의 차이 — 코드 11-16 / 11-17

코드 11-16 — Blocking

module seq_blocking (
    input  clk,
    input  a,
    input  b,
    input  c,
    input  d,
    input  e,
    output yout
);

reg m, n, yout;

always @(posedge clk) begin
    m    = ~(a & b);
    n    = c | d;
    yout = ~(m | n | e);
end

endmodule

blocking이므로 m과 n의 새 값이 같은 always 실행 안에서 yout 계산에 바로 사용된다. 11-11에서는 최종 yout만 FF에 저장되는 구조로 합성된다.

코드 11-17 — Nonblocking

module seq_Nonblocking (
    input  clk,
    input  a,
    input  b,
    input  c,
    input  d,
    input  e,
    output yout
);

reg m, n, yout;

always @(posedge clk) begin
    m    <= ~(a & b);
    n    <= c | d;
    yout <= ~(m | n | e);
end

endmodule

nonblocking에서는 같은 clock edge에서 우변들이 이전 상태를 기준으로 평가되므로 m, n, yout가 모두 상태로 저장된다. 11-12는 3개의 FF가 생성되는 모습을 보여준다.

5.3 4단 Shift Register에서 순서의 영향

코드 11-19(a) — Blocking, 앞에서 뒤로

always @(posedge clk) begin
    q0 = din;
    q1 = q0;
    q2 = q1;
    q3 = q2;
end

blocking에서는 새 q0가 즉시 q1에 전달되고, 다시 q2, q3로 같은 clock event 안에서 연쇄적으로 전달된다. 따라서 4단 shift register가 아니라 사실상 한 단계에 값이 연쇄 전달되는 구조가 된다.

코드 11-19(b) — Blocking, 뒤에서 앞으로

always @(posedge clk) begin
    q3 = q2;
    q2 = q1;
    q1 = q0;
    q0 = din;
end

이 순서는 앞 단계의 “이전 값”을 뒤 단계에 먼저 복사하므로 4단 shift register가 된다. 즉 blocking은 문장 순서에 따라 회로 의미가 바뀔 수 있다.

코드 11-20 — Nonblocking

always @(posedge clk) begin
    q0 <= din;
    q1 <= q0;
    q2 <= q1;
    q3 <= q2;
end
always @(posedge clk) begin
    q3 <= q2;
    q2 <= q1;
    q1 <= q0;
    q0 <= din;
end

두 코드 모두 우변이 edge 직전 값으로 평가되므로 동일한 4단 shift register가 된다.

6. 순차회로 코딩 가이드라인

  1. 플립플롭 또는 래치를 모델링하는 always 블록에서는 nonblocking(<=)을 사용한다.
  2. 조합회로를 모델링하는 always 블록에서는 blocking(=)을 사용한다.
  3. 동일 always 블록에서 순차회로와 조합회로를 함께 표현해야 한다면 nonblocking을 권장한다.
  4. 동일 always 블록에서 blocking과 nonblocking을 혼합하지 않는 것이 바람직하다.
  5. 여러 always 블록이 동일 reg를 구동하지 않도록 한다.

6.1 코드 11-21 — 권장/비권장 코딩

비권장 — 혼합 사용

always @(posedge clk or negedge rstn)
    if (!rstn)
        qout <= 1'b0;
    else begin
        tmp = a & b;
        qout <= tmp;
    end

권장 — 조합식을 nonblocking 우변으로 직접 사용

always @(posedge clk or negedge rstn)
    if (!rstn)
        qout <= 1'b0;
    else
        qout <= a & b;

권장 — 조합논리를 assign으로 분리

assign tmp = a & b;

always @(posedge clk or negedge rstn)
    if (!rstn)
        qout <= 1'b0;
    else
        qout <= tmp;

6.2 코드 11-22 — Multiple Driver

module Not_recommend_3 (
    input  clk,
    input  rstn,
    input  d1,
    input  d2,
    output qout
);

reg qout;

always @(posedge clk or negedge rstn)
    if (!rstn)
        qout <= 1'b0;
    else
        qout <= d1;

always @(posedge clk or negedge rstn)
    if (!rstn)
        qout <= 1'b0;
    else
        qout <= d2;

endmodule
다중 구동
같은 qout을 두 개의 always block이 동시에 구동하면 합성 오류나 합성 전/후 불일치의 원인이 될 수 있다. 한 상태 변수는 한 순차 always block에서만 갱신하는 구조가 기본이다.

7. 11.3 계수기와 시프트 레지스터

Counter(계수기)는 clock마다 상태값을 증가/감소시키며, 주파수 분주, 시간 계수, 제어신호 생성 등에 널리 사용된다.

7.1 동기식 vs 비동기식 계수기

구분동기식비동기식(Ripple)
Clock모든 FF가 같은 clock 사용앞단 출력이 다음 FF의 clock 역할
상태변화동시에 갱신앞단부터 순차 전파
장점빠르고 분석이 명확구조가 단순
단점조합논리가 더 필요할 수 있음전파지연 누적

7.2 11.3.1 8비트 증가계수기

코드 11-23

module counter_up (
    input        clk,
    input        rstn,
    output [7:0] cnt_out
);

reg [7:0] cnt_out;

always @(posedge clk or negedge rstn) begin
    if (!rstn)
        cnt_out <= 0;
    else
        cnt_out <= cnt_out + 1;
end

endmodule
현재 cnt_out → +1 Adder cnt_out + 1 → posedge clk 8-bit Register 저장
Bit Width
8비트 unsigned counter는 0~255를 표현한다. 255에서 +1을 하면 상위 carry는 잘리고 0으로 wrap-around된다.

코드 11-24 — 테스트벤치

module tb_counter;

reg clk, rstn;
wire [7:0] cnt_out;

counter_up u0 (
    clk,
    rstn,
    cnt_out
);

initial begin
    clk  = 1'b0;
    rstn = 1'b0;

    #5   rstn = 1'b1;
    #100 rstn = 1'b0;
    #20  rstn = 1'b1;

    #300 $finish;
end

always
    #10 clk = ~clk;

endmodule
설계과제 11-8 ~ 11-10
  • active-high enable을 갖는 8비트 down counter
  • mode에 따라 up/down이 바뀌는 8비트 counter
  • parallel load 기능까지 추가한 up/down counter

8. 11.3.2 주파수 분주기

1MHz master clock에서 100kHz pulse를 만드는 1/10 분주기를 예로 든다. 0~9까지 10개의 clock edge를 계수하고 cnt=9일 때 1 clock 동안 출력 pulse를 1로 만든다.

8.1 코드 11-25 — Duty 10% 1/10 분주

module freq_div10 (
    input  mclk,
    input  rst,
    output clk_div
);

reg [3:0] cnt;
reg clk_div;

always @(posedge mclk or posedge rst) begin
    if (rst) begin
        cnt     <= 0;
        clk_div <= 0;
    end
    else begin
        if (cnt == 9) begin
            cnt     <= 0;
            clk_div <= 1'b1;
        end
        else begin
            clk_div <= 1'b0;
            cnt     <= cnt + 1;
        end
    end
end

endmodule
mclk 10주기 → cnt 0→9 → clk_div 1주기 HIGH
Duty Cycle

9. 11.3.3 직렬입력-직렬출력 Shift Register

8비트 SISO(Serial-In Serial-Out) shift register는 클록 상승에지마다 데이터를 왼쪽으로 한 비트 이동시키고 s_in을 LSB로 받아 s_out을 MSB에서 출력한다.

module shift_reg_nblk1 (

        q[1] <= q[0];
        q[2] <= q[1];
        q[3] <= q[2];

        q[5] <= q[4];
        q[6] <= q[5];
        q[7] <= q[6];

endmodule

10.1 코드 11-29

module shifter_sp_io (
    input                   clk,
    input                   rstn,
    input                   shift_en,
    input                   pload_en,
    input                   pout_en,
    input                   sin,
    output                  sout,
    inout      [Len-1:0]    data_io
);

parameter Len = 8;

reg [Len-1:0] shift_reg;

assign data_io =
    (!pout_en) ? shift_reg : {Len{1'bz}};

assign sout = shift_reg[Len-1];

always @(posedge clk) begin
    if (!rstn)
        shift_reg <= {Len{1'b0}};
    else begin
        if (!shift_en) begin
            shift_reg    <= shift_reg << 1;
            shift_reg[0] <= sin;
        end
        else if (!pload_en)
            shift_reg <= data_io;
    end
end

endmodule
3-state 병렬출력
pout_en=0이면 내부 shift_reg가 data_io를 구동하고, 그 외에는 {Len{1'bz}}로 버스를 해제한다.
제어신호 상호배타성
parallel load와 shift가 동시에 활성되지 않아야 하며, 외부 장치가 data_io를 구동하는 동안 내부 parallel output도 동시에 구동되지 않아야 한다.

11. 11.3.5 선형 귀환 시프트 레지스터(LFSR)

LFSR(Linear Feedback Shift Register, 선형 귀환 시프트 레지스터)는 shift register의 일부 비트를 XOR/XNOR하여 입력으로 되먹임(feedback)함으로써 의사난수 비트열을 만든다.

응용 1

의사난수 sequence 생성

응용 2

암호화/복호화

응용 3

CRC·checksum 계열 무결성 검사

응용 4

BIST 테스트 벡터 생성/응답 분석

초기값 주의
XOR feedback LFSR을 모두 0으로 초기화하면 feedback도 계속 0이 되어 영원히 000… 상태에 갇힌다. XNOR 방식은 반대로 모든 비트를 1로 초기화하지 않도록 주의한다.

11.1 코드 11-31(a) — 잘못된 Blocking 모델

module LFSR_Bad1 (
    input        clk,
    input        rstn,
    output [2:0] qout
);

reg q3, q2, q1;
wire n1;

assign qout = {q3, q2, q1};
assign n1   = q1 ^ q3;

always @(posedge clk or negedge rstn)
    if (!rstn) begin
        {q3, q2, q1} = 3'b111;
    end
    else begin
        q3 = q2;
        q2 = n1;
        q1 = q3;
    end

endmodule

blocking으로 인해 q3가 먼저 바뀌고, 그 새 q3가 같은 edge 처리 중 q1에 다시 사용되면서 의도한 “동시에 한 칸 이동” 구조가 깨진다.

12.3 FSM 설계 권장사항

  1. 각 FSM을 독립 모듈로 구성한다.
  2. 상태 이름은 parameter로 정의한다.
  3. 초기 상태가 보장되도록 reset을 둔다.
  4. Next-State Logic / State Register / Output Logic을 분리한다.
  5. State Register는 latch보다 flip-flop을 사용한다.
  6. Next-State Logic은 case 중심으로 작성하고 undefined state는 default로 처리한다.

13. 11.4.1 Moore FSM

11-28은 네 상태 IDLE → READ → DLY → DONE을 갖는 FSM을 보여준다. go와 ws가 전이 조건으로 사용되며, 출력 rd, ds는 현재 상태에 의해 결정된다.

13.1 상태 흐름

IDLE go=1 → READ → DLY ws=0 → DONE → IDLE
DLY에서 ws=1
DONE으로 가지 않고 READ로 되돌아간다.

13.2 코드 11-32(a) — 출력 assign

module FSM_ex1 (
    input  clk,
    input  rstn,
    input  go,
    input  ws,
    output rd,
    output ds
);

parameter
    IDLE = 2'b00,
    READ = 2'b01,
    DLY  = 2'b10,
    DONE = 2'b11;

reg [1:0] state, next;

// State Register
always @(posedge clk or negedge rstn)
    if (!rstn)
        state <= IDLE;
    else
        state <= next;

// Next-State Logic
always @(state or go or ws) begin
    next = 2'bx;

    case (state)
        IDLE:
            if (go) next = READ;
            else    next = IDLE;

        READ:
            next = DLY;

        DLY:
            if (!ws) next = DONE;
            else     next = READ;

        DONE:
            next = IDLE;
    endcase
end

// Moore Output Logic
assign rd = (state == READ) ||
            (state == DLY);

assign ds = (state == DONE);

endmodule

13.3 코드 11-32(b) — Next-State block에서 출력도 계산

always @(state or go or ws) begin
    next = 2'bx;
    rd   = 1'b0;
    ds   = 1'b0;

    case (state)
        IDLE:
            if (go) next = READ;
            else    next = IDLE;

        READ: begin
            rd   = 1'b1;
            next = DLY;
        end

        DLY: begin
            rd = 1'b1;

            if (!ws) next = DONE;
            else     next = READ;
        end

        DONE: begin
            ds   = 1'b1;
            next = IDLE;
        end
    endcase
end
조합출력의 특징
state decoding을 통해 rd/ds가 직접 만들어진다. 조합경로의 입력이 변하면 출력도 조합논리 지연 후 변할 수 있다.

14. 11.4.2 Mealy FSM

입력 bit가 연속해서 00 또는 11이 되면 출력 dout_bit=1이 되는 sequence detector를 Mealy FSM으로 구현한다.

14.1 상태 역할

상태의미
start초기 상태
rd0_once직전 입력이 0인 상태
rd0_twice0이 연속 입력된 상태
rd1_once직전 입력이 1인 상태
rd1_twice1이 연속 입력된 상태

14.2 핵심 전이

rd0_once + din=0 → rd0_twice, dout=1
rd1_once + din=1 → rd1_twice, dout=1

14.3 코드 11-33 — Mealy FSM

module seq_det_mealy (
    input  clk,
    input  rst,
    input  din_bit,
    output dout_bit
);

reg [2:0] state_reg, next_state;

parameter
    start      = 3'b000,
    rd0_once   = 3'b001,
    rd1_once   = 3'b010,
    rd0_twice  = 3'b011,
    rd1_twice  = 3'b100;

// Next-State Logic
always @(state_reg or din_bit) begin
    case (state_reg)

        start:
            if (din_bit == 0)
                next_state = rd0_once;
            else if (din_bit == 1)
                next_state = rd1_once;
            else
                next_state = start;

        rd0_once:
            if (din_bit == 0)
                next_state = rd0_twice;
            else if (din_bit == 1)
                next_state = rd1_once;
            else
                next_state = start;

        rd0_twice:
            if (din_bit == 0)
                next_state = rd0_twice;
            else if (din_bit == 1)
                next_state = rd1_once;
            else
                next_state = start;

        rd1_once:
            if (din_bit == 0)
                next_state = rd0_once;
            else if (din_bit == 1)
                next_state = rd1_twice;
            else
                next_state = start;

        rd1_twice:
            if (din_bit == 0)
                next_state = rd0_once;
            else if (din_bit == 1)
                next_state = rd1_twice;
            else
                next_state = start;

        default:
            next_state = start;

    endcase
end

// State Register
always @(posedge clk or posedge rst) begin
    if (rst == 1)
        state_reg <= start;
    else
        state_reg <= next_state;
end

// Mealy Output Logic
assign dout_bit =
    (((state_reg == rd0_twice) && (din_bit == 0)) ||
     ((state_reg == rd1_twice) && (din_bit == 1)))
    ? 1'b1 : 1'b0;

endmodule
왜 Mealy인가?
출력 수식에 state_reg뿐 아니라 현재 입력 din_bit도 직접 들어간다. 즉 같은 상태에서도 din_bit 값에 따라 dout_bit가 달라질 수 있다.
