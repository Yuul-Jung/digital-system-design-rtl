1. CHAPTER 10 전체 개요

조합회로(combinational circuit, 현재 입력 조합만으로 출력이 결정되는 회로)는 논리 게이트들의 조합으로 구성되며, 과거 입력이나 이전 출력 상태를 저장하는 latch(래치) 또는 flip-flop(플립플롭)을 포함하지 않는다. 따라서 조합회로 RTL핵심은 모든 입력 변화와 모든 입력 조건에 대해 출력이 즉시 결정되는가이다.

기본 논리

AND, OR, XOR, NAND, NOR

선택·변환

MUX, Encoder, Decoder

연산·판단

Comparator, Adder, ALU

상수 데이터

Lookup Table(LUT)

조합회로대표 Verilog HDL 표현
기본 논리 게이트게이트 프리미티브, 비트/축약 연산자
멀티플렉서assign, ?:, if, case
인코더·디코더if, case, for
랜덤 로직·부울 함수연속 할당문과 논리/비트 연산자
비교기관계 연산자, if, for
LUTfunction + case
Simulation과 Synthesis 구분
테스트벤치에서 사용하는 initial, #delay, $finish는 DUT의 실제 FPGA 기능 회로로 해석하지 않는다. switch primitive, 불확정 반복, wait, force/release, fork/join 등도 일반 조합회로 합성용 구문과 구분한다.

2. 조합회로 모델링의 4가지 핵심 원칙

2.1 감지신호목록을 완전하게 작성

always 블록에서 읽는 모든 입력이 감지신호목록에 포함되어야 한다. 누락되면 합성된 회로와 RTL 시뮬레이션의 동작이 달라질 수 있다.

권장 표현
전통 Verilog에서는 always @(*) 또는 always @*를 사용하면 입력 누락 위험을 줄일 수 있다.

2.2 모든 조건에서 모든 출력값을 결정

if/case의 일부 조건에서 출력이 할당되지 않으면 이전 값을 유지해야 하므로 latch가 추론될 수 있다.

2.3 논리 최적화가 쉬운 구조 사용

같은 기능도 표현에 따라 논리 깊이와 합성 구조가 달라질 수 있다. 실제 면적과 timing은 합성·구현 보고서로 확인한다.

2.4 간결하고 명확한 코드

동일 기능을 여러 방식으로 표현할 수 있으므로, 회로 의도가 직접 드러나는 표현을 선택하면 오류와 디버깅 비용을 줄일 수 있다.

3. 10.1.1 기본 논리 게이트의 모델링

3입력 NOR를 네 방식으로 표현한다.

3.1 코드 10-1 — 비트 연산자

module nor3_bitop (
    input  [2:0] a,
    output       out_nor3
);

assign out_nor3 = ~(a[2] | a[1] | a[0]);

endmodule

3.2 코드 10-2 — 축약 NOR 연산자

module nor3_redop (
    input  [2:0] a,
    output       out_nor3
);

assign out_nor3 = ~|a;

endmodule
~|a를 풀어쓰면
~(a[2] | a[1] | a[0])과 동일하다.

3.3 코드 10-3 — 게이트 프리미티브

module nor3_gp (
    input  [2:0] a,
    output       out_nor3
);

nor (out_nor3, a[2], a[1], a[0]);

endmodule
포트 순서
게이트 프리미티브는 출력이 첫 번째이고 그 뒤에 입력이 온다.

3.4 코드 10-4 — if 조건문

module nor3_if (
    input  [2:0] a,
    output       out_nor3
);

reg out_nor3;

always @(a) begin
    if (a == 3'b000)
        out_nor3 = 1'b1;
    else
        out_nor3 = 1'b0;
end

endmodule

3.5 코드 10-5 — 테스트벤치

module tb_nor3;
reg [2:0] a;
integer i;

nor3_bitop U0 (a, out_nor3);
// nor3_redop U1 (a, out_nor3);
// nor3_gp    U2 (a, out_nor3);
// nor3_if    U3 (a, out_nor3);

initial begin
    for (i = 0; i <= 7; i = i + 1) begin
        a = i;
        #10;
    end
    #20 $finish;
end
endmodule
설계과제 10-1

3입력 NAND를 비트 연산자, 축약 연산자, 게이트 프리미티브, if 조건문의 네 방법으로 모델링하고 검증한다.

4. 10.1.2 멀티비트 논리연산

4비트 a와 b의 XOR는 실제 회로에서 2입력 XOR 게이트 4개가 병렬로 존재하는 구조이다.

4.1 코드 10-6 — 프리미티브 배열

module xor4b_gp (
    input  [3:0] a,
    input  [3:0] b,
    output [3:0] xor4b
);

xor U0 [3:0] (xor4b, a, b);

endmodule

4.2 코드 10-7 — 벡터 비트 연산

module xor4b_bitop (
    input  [3:0] a,
    input  [3:0] b,
    output [3:0] xor4b
);

assign xor4b = a ^ b;

// 비트별로 풀어쓰면
// xor4b[0] = a[0] ^ b[0]
// xor4b[1] = a[1] ^ b[1]
// xor4b[2] = a[2] ^ b[2]
// xor4b[3] = a[3] ^ b[3]

endmodule

4.3 코드 10-8 — for 반복문

module xor4b_for (
    input  [3:0] a,
    input  [3:0] b,
    output [3:0] xor4b
);

reg [3:0] xor4b;
integer i;

always @(a or b) begin
    for (i = 0; i < 4; i = i + 1)
        xor4b[i] = a[i] ^ b[i];
end

endmodule
for의 합성 의미
4클록 동안 반복하는 구조가 아니라, 고정 반복 횟수만큼 병렬 XOR 논리가 전개된다.

4.4 코드 10-9 — 테스트벤치

module tb_xor4b;
reg  [3:0] a, b;
wire [3:0] out_xor4b;

xor4b_gp U0 (a, b, out_xor4b);
// xor4b_bitop U1 (a, b, out_xor4b);
// xor4b_for   U2 (a, b, out_xor4b);

initial begin
    a = 4'b0000; b = 4'b0000;
    #10 a = 4'b1010; b = 4'b0101;
    #10 a = 4'b1100; b = 4'b1100;
    #10 a = 4'b1011; b = 4'b0000;
    #10 a = 4'b1001; b = 4'b1000;
    #10 a = 4'b1111; b = 4'b0000;
    #10 a = 4'b0010; b = 4'b0111;
    #10 a = 4'b1101; b = 4'b0101;
    #10 a = 4'b0000; b = 4'b1101;
    #10 a = 4'b1111; b = 4'b1111;
    #10 a = 4'b0111; b = 4'b0100;
    #20 $finish;
end
endmodule

6. 10.2 멀티플렉서

4개의 4비트 입력 중 하나를 2비트 sel로 선택한다. if, 조건 연산자, case 세 표현이 같은 MUX로 합성되는 것을 보여준다.

6.1 코드 10-14 — if

module mux4to1_if (
    input [3:0] a, b, c, d,
    input [1:0] sel,
    output [3:0] mux_out
);
reg [3:0] mux_out;
always @(sel or a or b or c or d) begin
    if      (sel == 2'b00) mux_out = a;
    else if (sel == 2'b01) mux_out = b;
    else if (sel == 2'b10) mux_out = c;
    else if (sel == 2'b11) mux_out = d;
    else                    mux_out = 4'bx;
end
endmodule

6.2 코드 10-15 — 조건 연산자

module mux4to1_conop (
    input [3:0] a, b, c, d,
    input [1:0] sel,
    output [3:0] mux_out
);
assign mux_out =
    (sel == 0) ? a :
    (sel == 1) ? b :
    (sel == 2) ? c :
    (sel == 3) ? d : 4'bx;
endmodule

6.3 코드 10-16 — case

module mux4to1_case (
    input [3:0] a, b, c, d,
    input [1:0] sel,
    output [3:0] mux_out
);
reg [3:0] mux_out;
always @(sel or a or b or c or d) begin
    case (sel)
        0: mux_out = a;
        1: mux_out = b;
        2: mux_out = c;
        3: mux_out = d;
        default: mux_out = 4'bx;
    endcase
end
endmodule

6.4 코드 10-17 — 테스트벤치

module tb_mux41;

reg  [3:0] a, b, c, d;
reg  [1:0] sel;
wire [3:0] mux_if;
wire [3:0] mux_case;
wire [3:0] mux_conop;

mux4to1_if u0 (
    a, b, c, d, sel, mux_if
);

mux4to1_case u1 (
    a, b, c, d, sel, mux_case
);

mux4to1_conop u2 (
    a, b, c, d, sel, mux_conop
);

initial begin
    a = 4'b0001;
    b = 4'b0010;
    c = 4'b0100;
    d = 4'b1000;
    sel = 2'b00;

    #80;
    a = 4'b1100;
    b = 4'b0011;
    c = 4'b0110;
    d = 4'b1001;

    #80 $finish;
end

always
    #20 sel = sel + 1'b1;

always @(*) begin
    if ((mux_if !== mux_case) ||
        (mux_if !== mux_conop))
        $display(
            "MUX mismatch: t=%0t sel=%b if=%h case=%h conop=%h",
            $time, sel, mux_if, mux_case, mux_conop
        );
end

endmodule

7.1 코드 10-19 — case

module enc_4to2_case (
    input [3:0] enc_in,
    output [1:0] enc_out
);
reg [1:0] enc_out;
always @(enc_in) begin
    case (enc_in)
        4'b0001: enc_out = 2'b00;
        4'b0010: enc_out = 2'b01;
        4'b0100: enc_out = 2'b10;
        4'b1000: enc_out = 2'b11;
        default: enc_out = 2'bxx;
    endcase
end
endmodule

7.2 코드 10-20 — if

module enc_4to2_if (
    input [3:0] enc_in,
    output [1:0] enc_out
);
reg [1:0] enc_out;
always @(enc_in) begin
    if      (enc_in == 4'b0001) enc_out = 2'b00;
    else if (enc_in == 4'b0010) enc_out = 2'b01;
    else if (enc_in == 4'b0100) enc_out = 2'b10;
    else if (enc_in == 4'b1000) enc_out = 2'b11;
    else                         enc_out = 2'bxx;
end
endmodule

7.3 코드 10-21 — for

module enc_4to2_for (
    input [3:0] enc_in,
    output [1:0] enc_out
);
reg [1:0] enc_out;
reg [3:0] temp;
integer n;
always @(enc_in) begin
    temp = 4'b0001;
    enc_out = 2'bxx;
    for (n = 0; n < 4; n = n + 1) begin
        if (enc_in == temp) enc_out = n;
        temp = temp << 1;
    end
end
endmodule

8. 10.3.2 우선순위 인코더

여러 입력이 동시에 1일 수 있고, MSB인 enc_in[3]이 가장 높은 우선순위를 갖는다. valid는 입력에 최소 한 개의 1이 존재할 때 1이다.

enc_inenc_outvalid
1xxx111
01xx101
001x011
0001001
0000xx0

8.1 코드 10-23 — if

module pri_enc_4to2_if (
    input [3:0] enc_in,
    output valid,
    output [1:0] enc_out
);
reg valid;
reg [1:0] enc_out;
always @(enc_in) begin
    valid = 1'b1;
    if      (enc_in[3]) enc_out = 2'b11;
    else if (enc_in[2]) enc_out = 2'b10;
    else if (enc_in[1]) enc_out = 2'b01;
    else if (enc_in[0]) enc_out = 2'b00;
    else begin
        valid = 1'b0;
        enc_out = 2'bxx;
    end
end
endmodule

8.2 코드 10-24 — casex

module pri_enc_4to2_case (
    input [3:0] enc_in,
    output valid,
    output [1:0] enc_out
);
reg valid;
reg [1:0] enc_out;
always @(enc_in) begin
    valid = 1'b1;
    casex (enc_in)
        4'b1xxx: enc_out = 2'b11;
        4'b01xx: enc_out = 2'b10;
        4'b001x: enc_out = 2'b01;
        4'b0001: enc_out = 2'b00;
        default: begin
            valid = 1'b0;
            enc_out = 2'bxx;
        end
    endcase
end
endmodule

8.3 코드 10-25 — for + disable

module pri_enc_4to2_for (
    input [3:0] enc_in,
    output valid,
    output [1:0] enc_out
);
reg valid;
reg [1:0] enc_out;
integer n;
always @(enc_in) begin : Loop
    valid = 0;
    enc_out = 2'bxx;
    for (n = 3; n >= 0; n = n - 1)
        if (enc_in[n]) begin
            valid = 1;
            enc_out = n;
            disable Loop;
        end
end
endmodule

8.4 코드 10-26 — 테스트벤치

module tb_pri_enc_4to2;

    end
    #10 $finish;
end

10.3 코드 10-35 — MSB 우선 for 비교

module comp_for (
    input [SIZE-1:0] a,
    input [SIZE-1:0] b,
    output aeqb,
    output agtb,
    output altb
);
parameter SIZE = 4;
reg aeqb, agtb, altb;
integer i;
always @(a or b) begin : Loop_Comp
    aeqb = 1'b1;
    agtb = 1'b0;
    altb = 1'b0;
    for (i = SIZE-1; i >= 0; i = i - 1) begin
        if (a[i] != b[i]) begin
            agtb = a[i];
            altb = ~a[i];
            aeqb = 1'b0;
            disable Loop_Comp;
        end
    end
end
endmodule

12. 10.6 case 문과 if 문의 합성

조합회로에서 일부 입력 조건에 대한 출력 할당이 빠지면 이전 값을 유지해야 하므로 latch가 합성된다.

12.1 코드 10-42 — 불완전한 case

module case_latch (
    input [1:0] sel,
    input [7:0] in1,
    input [7:0] in2,
    output [7:0] out
);
reg [7:0] out;
always @(sel, in1, in2) begin
    case (sel)
        2'b01: out = in1;
        2'b10: out = in2;
    endcase
end
endmodule
sel=01 → in1sel=10 → in2sel=00/11 → 할당 없음→이전값 유지 → latch

12.2 코드 10-43 — else가 없는 if

module if_latch (
    input [1:0] sel,
    input [7:0] in1,
    input [7:0] in2,
    output [7:0] out
);
reg [7:0] out;

    if (sel == 2'b01) out = in1;
    else if (sel == 2'b10) out = in2;

endmodule

13. 10.6.2 다중 if 문의 합성

13.1 코드 10-49 — 독립 if의 연속 사용

module if_if (
    input selA, selB, selC, selD,
    input [3:0] dinA, dinB, dinC, dinD, dinE,
    output [3:0] dout
);
reg [3:0] dout;
always @(*) begin
    dout = dinE;
    if (selA) dout = dinA;
    if (selB) dout = dinB;
    if (selC) dout = dinC;
    if (selD) dout = dinD;
end
endmodule
기능 우선순위
여러 sel이 동시에 1이면 뒤의 할당이 앞의 값을 덮어쓰므로 기능적으로 selD > selC > selB > selA 순의 우선순위를 갖는다.

13.2 코드 10-50 — if-else-if

module if_else_if (
    input selA, selB, selC, selD,
    input [3:0] dinA, dinB, dinC, dinD, dinE,
    output [3:0] dout
);
reg [3:0] dout;
always @(*) begin
    if      (selA) dout = dinA;
    else if (selB) dout = dinB;
    else if (selC) dout = dinC;
    else if (selD) dout = dinD;
    else           dout = dinE;
end
endmodule
기능 우선순위
앞 조건이 참이면 뒤 조건은 선택되지 않으므로 selA > selB > selC > selD 순이다.
Timing 관점
우선순위 구조는 MUX 체인의 논리 깊이에 영향을 줄 수 있다. 하지만 실제 합성기는 논리 최적화를 수행하므로 최종 critical path는 Synthesis/Implementation 결과와 Timing Report로 확인해야 한다.
