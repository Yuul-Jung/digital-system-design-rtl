1. CHAPTER 08 전체 개요

컴파일러 지시어(compiler directive, 컴파일러 디렉티브)는 Verilog HDL 소스코드가 어떻게 컴파일되는지에 영향을 주는 명령어이다. 회로의 논리연산 자체를 표현하는 문장이 아니라, 컴파일 전에 소스코드를 치환·선택·삽입하거나 시뮬레이션 시간 단위를 지정하는 역할을 한다.

문자 매크로

`define, `undef

반복되는 문자·상수·코드 조각을 이름으로 정의하고 치환한다.

시간 단위/정밀도

`timescale

#delay가 실제 몇 ns/us인지와 반올림 정밀도를 지정한다.

파일 삽입

`include

별도 파일 내용을 현재 소스 위치에 삽입한다.

선택적 컴파일

`ifdef, `ifndef, `elsif, `else, `endif

정의된 매크로에 따라 컴파일할 소스 부분을 선택한다.

학습 목표
① `timescale을 이용하여 시간과 지연의 단위·정밀도를 지정한다.
② `include를 이용해 파일을 삽입한다.
③ `ifdef, `else 등을 이용해 선택적으로 컴파일한다.
④ `define을 이용해 문자 매크로를 정의하고 사용한다.
RTL 관점
컴파일러 지시어는 레지스터, 게이트, MUX 같은 하드웨어 그 자체가 아니다. 그러나 어떤 코드가 최종 컴파일 대상에 포함되는지, 상수나 폭이 무엇으로 치환되는지에 따라 최종 RTL 구조와 시뮬레이션 결과에는 직접적인 영향을 줄 수 있다.

2. 컴파일러 지시어의 기본 규칙

Verilog HDL의 컴파일러 지시어는 grave accent / backtick(`) 문자로 시작한다. 이는 단일 인용부호(')와 다른 문자이므로 구분해야 한다.

세미콜론을 붙이지 않는다.
컴파일러 지시어는 Verilog HDL의 일반 문장이 아니므로 문장 끝에 ;를 붙이지 않는다.

2.1 적용 범위

컴파일러 지시어는 등장한 위치부터 다른 지시어에 의해 변경되거나 컴파일이 끝날 때까지 이후 소스에 영향을 미칠 수 있다. 소스 파일 어디에나 둘 수 있지만 일반적으로 모듈 정의 앞부분에 배치하는 것을 권장한다.

2.2 IEEE-1364 표준 지시어 예

`celldefine
`default_nettype
`define
`else
`elsif
`end_keywords
`endcelldefine
`endif

3. 8.1 문자 매크로 정의 및 해제 지시어

`define은 Verilog HDL 소스코드의 문자 치환을 위한 문자 매크로(text macro, 텍스트 매크로)를 정의한다. C 언어의 #define과 유사한 기능이라고 설명한다.

`define macro_name [(arguments)] text_string [(arguments)]
`undef macro_name
`macro_name [(arguments)]
지시어역할
`define컴파일 과정에서 치환될 매크로 이름과 치환 문자열 정의
`undef기존 매크로 정의 해제
`macro_name정의된 매크로를 실제 소스에서 사용
왜 사용하는가?
비트 폭, 지연값, 반복되는 상수처럼 여러 위치에서 같은 값이 사용될 때 매크로 정의 한 곳만 수정하면 전체 치환 결과가 함께 바뀌므로 소스 관리가 쉬워진다.

3.1 wordsize 예

예시 8-1
`define wordsize 32

reg [1:`wordsize] data;
`wordsize → 컴파일 전 치환 32 → reg [1:32] data
매크로는 문자 치환
`wordsize라는 하드웨어 신호가 만들어지는 것이 아니다. 컴파일러가 소스 텍스트를 처리할 때 해당 위치를 문자 32로 바꾼다.

3.2 매크로 이름 제한

`define, `timescale 등 컴파일러 지시어 자체가 미리 정의된 이름처럼 취급되므로 이를 다시 매크로 이름으로 정의할 수 없다고 설명한다.

3.3 여러 줄 매크로

기본적으로 치환 문자열은 같은 줄에서 정의되며, 여러 줄이 필요하면 backslash(\)로 줄을 이어 작성할 수 있다. 다만 문자열·숫자·식별자·키워드·연산자 자체를 문법적으로 중간에서 부적절하게 분할하면 안 된다.

문법 오류 예 
`define first_half "start of string

$display(`first_half end of string");

문자열의 일부만 매크로로 정의하여 정상적인 문자열 토큰을 깨뜨리는 형태이므로 문법 오류가 된다.

4. 인수를 갖는 문자 매크로

매크로에 인수(argument)를 정의하면 같은 매크로를 호출할 때마다 다른 값을 넣어 서로 다른 코드로 치환할 수 있다.

4.1 주기 20ns 클록 예

예시 8-3
`define period 20   // 세미콜론 없음

reg clk;

initial
    clk = 1'b0;

always
    #(`period/2) clk = ~clk;
`period = 20 → `period/2 = 10 → 10ns마다 clk 반전 → 주기 20ns

4.2 가변 지연 NAND 매크로

예시 8-4
// variable delay NAND gate
`define NAND_var_dly(d_val) nand #(d_val)

`NAND_var_dly(2) u1 (y1, a, b);
// 치환 후: nand #(2) u1 (y1, a, b);

`NAND_var_dly(5) u2 (y2, a, b);
// 치환 후: nand #(5) u2 (y2, a, b);
핵심
한 개의 매크로 정의로 지연값만 다른 NAND 게이트 문장을 반복 생성할 수 있다.
매크로 치환 규칙
매크로 치환 문자열은 비어 있을 수 있으며, 단일 라인 주석은 치환 문자열에 포함되지 않는다.

5. 8.2 시간 단위와 정밀도 지정 지시어

Verilog HDL의 #10, #1.55 같은 지연값은 그 자체만으로 ns인지 us인지 알 수 없다. `timescale은 이 지연값이 의미하는 시간 단위(time unit)와 시간 정밀도(time precision)를 지정한다.

`timescale time_unit / time_precision
대표 예
`timescale 1ns / 1ps

`timescale 10us / 100ns
항목의미
time_unit소스에서 지연값 1이 의미하는 실제 시간 크기
time_precision지연값을 어느 정밀도까지 표현/반올림할지 결정

5.1 시간 단위 기호

s초
ms밀리초
us마이크로초
ns나노초
ps피코초
fs펨토초
정밀도 규칙
time precision은 time unit보다 더 거친 단위로 지정할 수 없다. 즉, 시간 단위보다 같거나 더 세밀한 정밀도를 사용해야 한다.

5.2 지시어의 효력

  • 다른 `timescale이 나타날 때까지 효력이 유지된다.
  • `timescale이 없으면 시뮬레이터 설정에 따라 달라질 수 있다.
  • `resetall로 초기화되면 기존 timescale 설정이 기본값으로 되돌아간다.
  • 설계에 여러 timescale이 존재하면 전체 시뮬레이션 해상도는 가장 작은 time precision의 영향을 받는다.

6. `timescale 계산 예

6.1 예 ① — 1ns / 1ps

`timescale 1ns / 1ps
  • 지연값 1 → 1ns
  • 정밀도 1ps → 0.001ns 단위까지 표현
  • 즉, ns 기준 소수점 이하 3자리 정밀도

6.2 예 ② — 10us / 100ns

`timescale 10us / 100ns
  • 지연값 1 → 10us
  • 정밀도 100ns → 0.1us
  • 즉, 10us 단위를 기준으로 소수점 이하 1자리 정밀도

6.3 코드 8-1 — 1.55가 실제 16ns가 되는 과정

코드 8-1
`timescale 10ns / 1ns

module test;

reg set;

parameter d = 1.55;

initial begin
    #d set = 0;
    #d set = 1;
end

endmodule
① 시간 정밀도 적용
시간 단위는 10ns이고 정밀도는 1ns이므로, 소스의 지연값은 0.1 time-unit 단위로 표현된다. 1.55는 1.6으로 반올림된다.
② 실제 시간 변환
1.6 × 10ns → 16ns
③ 첫 번째 할당
시뮬레이션 시간 16ns에 set = 0
④ 두 번째 지연 누적
다시 16ns가 지나므로 시뮬레이션 시간 32ns에 set = 1
코드상의 지연정밀도 반올림실제 시간
#1.551.616ns
다음 #1.551.6누적 32ns
실제 FPGA와 구분
`timescale은 시뮬레이션에서 #delay를 해석하는 시간 기준이다. FPGA의 실제 배선·셀 지연이나 최대 동작주파수를 지정하는 타이밍 제약과는 다른 개념이다.

7. 8.3 파일 삽입 지시어

`include는 다른 소스 파일의 내용 전체를 현재 소스의 해당 위치에 삽입한다. 컴파일러 입장에서는 삽입된 파일의 코드가 원래 현재 파일 안에 작성되어 있던 것처럼 처리된다.

`include "filename"

7.1 주요 이점

  • 설계 전체 구성 관리가 쉬워진다.
  • 소스코드를 기능별 파일로 분리해 구성할 수 있다.
  • 공통 함수·태스크·매크로 등을 여러 소스에서 재사용하기 쉽다.

7.2 삽입 위치

`include는 소스 어디에나 위치할 수 있으며, 삽입 파일 내부에 다시 다른 `include를 둘 수도 있다.

7.3 코드 8-2 — BCD 카운터와 FND 변환 함수

코드 8-2
module bcd_cnt_fnd (
    input        clk,
    input        rst,
    output [7:0] fnd_data,
    output       fnd_scan
);

wire [3:0] cnt;

`include "bcd_to_fnd.v"
// 이 위치에 bcd_to_fnd.v의 내용이 삽입되어 컴파일됨

bcd_counter u0 (
    clk,
    rst,
    cnt
);

assign fnd_data = bcd_to_fnd(cnt);
assign fnd_scan = 1'b0;

endmodule
bcd_to_fnd.v → `include 현재 위치에 텍스트 삽입 → 하나의 소스처럼 컴파일
이 예의 의미
FND 변환 기능을 현재 모듈 안에 매번 직접 작성하지 않고 별도 파일로 관리한 뒤 컴파일 시 포함한다.

8. 8.4 선택적 컴파일 지시어

선택적 컴파일은 특정 매크로가 정의되어 있는지 여부에 따라 소스 일부만 컴파일에 포함한다.

`ifdef macro_name source_code `elsif other_macro source_code `else source_code `endif
`ifndef macro_name source_code `elsif other_macro source_code `else source_code `endif

8.1 대표적인 사용 목적

  • 행위수준 / 구조적 / 게이트 수준 모델 중 하나 선택
  • 서로 다른 타이밍 정보나 비트 폭 선택
  • 테스트벤치에서 여러 입력 벡터 중 하나 선택
하드웨어 관점
선택적 컴파일은 런타임 MUX가 아니다. 컴파일 전에 조건에 따라 특정 코드만 남기므로, 선택되지 않은 분기의 RTL은 최종 컴파일 대상에서 제외된다.

9. `ifdef · `ifndef · `elsif · `else · `endif

`ifdef macro_name

매크로가 정의되어 있으면 해당 블록을 컴파일한다.

`ifndef macro_name

매크로가 정의되어 있지 않으면 해당 블록을 컴파일한다.

`elsif macro_name

앞 조건이 선택되지 않았고 해당 매크로가 정의되어 있으면 이 블록을 컴파일한다.

`else

앞선 조건들이 모두 선택되지 않았을 때 사용한다.

`endif

선택적 컴파일 범위를 종료한다.

9.1 동작 정리

상태`ifdef`ifndef
매크로가 정의됨 해당 블록 포함 해당 블록 제외
매크로가 정의되지 않음 해당 블록 제외 해당 블록 포함

9.2 다중 `elsif

여러 `elsif가 존재하면 소스에 나열된 순서대로 검사하며 처음 조건을 만족하는 분기가 컴파일 대상이 된다.

9.3 코드 8-3 — behavioral / gate 모델 선택

코드 8-3
module and_op (
    input  a,
    input  b,
    output c
);

`ifdef behavioral

wire c = a & b;

`else

and u0 (
    c,
    a,
    b
);

`endif

endmodule
behavioral 정의됨 → wire c = a & b
behavioral 정의 안 됨 → and gate primitive
두 코드는 AND 기능을 서로 다른 방식으로 모델링
매크로 정의 여부에 따라 둘 중 하나만 컴파일된다.

10. 내포된 선택적 컴파일

`ifdef, `ifndef, `else, `elsif, `endif는 서로 중첩하여 사용할 수 있다.

코드 8-4
module test;

`define wow
`define nest_one
`define second_nest

`ifdef wow

initial
    $display("wow is defined");

    `ifdef nest_one

    initial
        $display("nest_one is defined");

        `ifdef nest_two

        initial
            $display("nest_two is defined");

        `else

        initial
            $display("nest_two is not defined");

        `endif

    `else

    initial
        $display("nest_one is not defined");

    `endif

`else

initial
    $display("wow is not defined");

    `ifdef second_nest

    initial
        $display("nest_two is defined");

    `else

    initial
        $display("nest_two is not defined");

    `endif

`endif

endmodule

10.1 매크로 상태

매크로정의 여부
wow정의됨
nest_one정의됨
second_nest정의됨
nest_two정의되지 않음

10.2 컴파일되는 분기

① `ifdef wow
wow가 정의되어 있으므로 첫 번째 참 분기로 진입
② `ifdef nest_one
nest_one도 정의되어 있으므로 참 분기로 진입
③ `ifdef nest_two
nest_two는 정의되어 있지 않으므로 `else 분기 선택

10.3 실행 결과

wow is defined
nest_one is defined
nest_two is not defined

11. `resetall 지시어

`resetall을 컴파일러 지시어 상태를 기본값으로 초기화하는 지시어로 설명한다.

`resetall

11.1 권장 사용 흐름

`resetall
`timescale 1ns / 1ps
`define SOME_OPTION

module example (
    input  a,
    input  b,
    output y
);

`ifdef SOME_OPTION
assign y = a & b;
`else
assign y = a | b;
`endif

endmodule
`resetall → 기존 지시어 상태 초기화 → 현재 파일에 필요한 지시어 다시 지정
권장 사항
특정 소스 파일에 필요한 지시어만 명확히 활성화하기 위해 파일 처음에 `resetall을 배치하고 그 뒤에 원하는 컴파일러 지시어를 나열하는 방법이 유용하다고 설명한다.
`define과 `resetall
문자 매크로 정의는 `resetall로 초기화되지 않는다. 지시어마다 resetall의 영향 범위가 다르므로 구분해서 사용한다.

`undef 매크로 정의 해제 이후 선택적 컴파일 조건이 달라지는가?
`timescale 시간 단위와 정밀도 지정 #1이 실제 몇 ns/us인가?
`include 외부 파일 삽입 어떤 파일 내용이 어느 위치에 들어오는가?
`ifdef 매크로가 정의된 경우 컴파일 현재 해당 매크로가 정의되어 있는가?
`ifndef 매크로가 정의되지 않은 경우 컴파일 반대 조건 분기인가?
`elsif 추가 조건 분기 앞 분기가 선택되지 않았는가?
`else 나머지 분기 앞 조건들이 모두 실패했는가?
`endif 조건부 컴파일 종료 중첩 구조의 어느 ifdef를 닫는가?
`resetall 지시어 상태 기본값 초기화 파일 시작 상태를 명확히 하는가?

Compiler → RTL 연결
컴파일러 지시어는 직접 논리회로를 표현하지 않지만, 컴파일 전에 상수와 코드를 치환하고, 파일을 삽입하고, 특정 구현만 선택하기 때문에 최종적으로 컴파일·합성되는 RTL의 형태를 결정할 수 있다. 반면 `timescale은 주로 시뮬레이션 시간 해석에 관련되며, 실제 FPGA Timing Constraint(타이밍 제약)와 구분해야 한다.
