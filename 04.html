1. CHAPTER 04 개요

할당문은 net 또는 variable에 값을 주는 가장 기본적인 방법이다. Verilog HDL의 기본 할당을 연속 할당(continuous assignment)과 절차형 할당(procedural assignment)의 두 종류로 구분한다.

① 연속 할당

net 자료형 신호에 값을 할당한다.

대표 구문: assign

우변 값이 변하면 자동으로 다시 평가되어 좌변 net을 구동한다.

② 절차형 할당

variable 자료형 변수에 값을 할당한다.

always, initial, task, function 내부에서 사용한다.

blocking은 =, nonblocking은 <=를 사용한다.

추가 형태
기본적인 두 할당 외에 절차형 연속 할당(Procedural Continuous Assignment, PCA)인 assign-deassign과 force-release도 별도로 설명한다.

1.1 할당문을 읽을 때 확인할 것

좌변 자료형은? → net / variable → 언제 값이 갱신되는가? → 회로 구조·시뮬레이션 의미 결정

2. 4.1.1 연속 할당문

연속 할당문은 assign을 이용하여 net에 스칼라, 벡터 또는 벡터 일부 값을 할당한다. 논리식으로 표현된 조합회로를 모델링할 때 사용된다.

assign [drive_strength] [delay3] net_lvalue = expression {, net_lvalue = expression};
  • 할당 기호는 =를 사용한다.
  • 좌변은 net 자료형이어야 하며 variable은 사용할 수 없다.
  • 콤마로 여러 연속 할당을 하나의 assign 문에 작성할 수 있다.
  • #로 전달지연을 지정할 수 있으며, 생략하면 0으로 간주한다.
  • 우변 수식 값에 event가 발생하면 좌변 net이 자동으로 갱신된다.
  • 서로 독립된 연속 할당문의 소스 코드 순서는 시뮬레이션·합성 결과에 영향을 주지 않는다.
하드웨어 관점
assign y = expression;은 “이 문장이 한 번 실행된다”가 아니라, expression을 구현한 조합논리가 계속 y를 구동한다고 이해하는 것이 정확하다.
코드 4-1: 연속 할당문을 이용한 조합회로
module logic_assign (
    input  inA,
    input  inB,
    input  inC,
    input  inD,
    output [4:0] y
);

assign y[0] = inA | inB & inC;

assign y[1] = inA ~^ inB,
       y[2] = inC ^ inD;

assign y[4:3] = {inA, inB} | {inC, inD};

endmodule

2.1 각 문장의 회로 의미

코드의미
y[0] = inA | inB & inC inB & inC 계산 후 inA와 OR 하는 조합논리
y[1], y[2] 한 개의 assign 문에 두 연속 할당을 콤마로 나열
y[4:3] 5비트 출력 벡터 중 상위 2비트만 한 번에 할당
우선순위
첫 번째 식은 연산자 우선순위 때문에 inB & inC가 먼저 평가된다. 복잡한 수식에서는 괄호를 사용해 의도를 명확히 하는 것이 좋다.

3. 함축적 연속 할당문

net 선언문과 연속 할당문을 한 문장에 함께 쓸 수 있으며, 이를 함축적 연속 할당문이라고 설명한다.

예시 4-1
wire mynet = enable & data;

위 표현은 다음과 동일한 의미이다.

예시 4-2
wire mynet;
assign mynet = enable & data;
enable 또는 data 변화 → enable & data 재평가 → mynet 자동 갱신

4. 연속 할당을 이용한 회로 모델링

4.1 4비트 가산기

코드 4-2
module adder_4b (
    input  [3:0] ina,
    input  [3:0] inb,
    input        carry_in,
    output       carry_out,
    output [3:0] sum_out
);

assign {carry_out, sum_out} = ina + inb + carry_in;

endmodule
ina[3:0] + inb[3:0] + carry_in → 5비트 결과 → {carry_out, sum_out[3:0]}
결합 연산자의 역할
4비트 + 4비트 + carry 연산에서 발생할 수 있는 최상위 carry를 carry_out으로 받고, 하위 4비트를 sum_out으로 받는다.

4.2 16비트 출력 버스 선택 회로

코드 4-3은 4개의 입력 버스 중 하나를 선택하여 내부 data net에 연결하고, enable에 따라 최종 출력 bus_out을 구동하거나 high-impedance(z) 상태로 만드는 예이다.

코드 4-3
module select_bus (
    output [n:1] bus_out,
    input  [n:1] bus0,
    input  [n:1] bus1,
    input  [n:1] bus2,
    input  [n:1] bus3,
    input        enable,
    input  [1:0] sel
);

parameter n   = 16;
parameter Zee = 16'bz;

tri [n:1] data;

// 연속 할당을 포함한 net 선언
tri [n:1] bus_out = enable ? data : Zee;

// 하나의 assign 문에 4개의 연속 할당
assign
    data = (sel == 0) ? bus0 : Zee,
    data = (sel == 1) ? bus1 : Zee,
    data = (sel == 2) ? bus2 : Zee,
    data = (sel == 3) ? bus3 : Zee;

endmodule

신호 흐름

bus0~bus3 → sel에 따라 한 버스 구동 → tri data → enable ? data : z → bus_out
이 예핵심
data는 여러 연속 할당에 의해 구동되는 tri net이며, 선택되지 않은 경로는 z를 출력한다. 따라서 실제로 선택된 하나의 입력 버스만 내부 bus를 구동하도록 모델링한다.

5. 4.1.2 할당 지연과 net 지연

5.1 연속 할당문의 지연

assign 뒤에 #을 사용하면 우변 값이 변한 시점부터 좌변 net에 그 값이 반영될 때까지의 전달지연을 지정할 수 있다.

예시 4-3
assign #10 wireA = a & b;
a 또는 b 변화 → a & b 평가 10 time unit wireA 갱신

함축적 연속 할당에서도 같은 지연을 지정할 수 있다.

예시 4-4
wire #10 wireA = a & b;
동작 기준
위 표현은 net 지연이 아니라 연속 할당문의 지연로 처리된다. 즉, 이 선언 안에 포함된 특정 연속 할당에 적용된다.

5.2 net 지연

예시 4-5
wire #10 wireA;

이 경우에는 wireA 자체에 10 time unit의 net 지연이 지정된다. 따라서 해당 net을 구동하는 게이트 프리미티브, 연속 할당문 등 모든 구동자의 결과가 wireA에 반영될 때 이 지연의 영향을 받는다.

표현의미
assign #10 wireA = ...; 특정 연속 할당문의 지연
wire #10 wireA = ...; 함축적 연속 할당문의 지연
wire #10 wireA; wireA net 자체의 지연

5.3 벡터 net에 적용되는 지연 규칙

  • 우변이 0이 아닌 값에서 0으로 천이 → 하강지연
  • 우변이 z로 천이 → turn-off 지연
  • 그 외의 변화 → 상승지연
벡터 net의 지연
벡터 net에 대한 할당에서는 상승/하강지연이 개별 비트마다 독립적으로 적용되는 것이 아니라 벡터 전체 값의 천이에 대해 일괄 적용된다고 설명한다.

6. 연속 할당문의 관성지연

Verilog HDL에는 기본적으로 inertial delay(관성지연, 짧은 펄스 제거 특성)가 적용된다. 지정된 지연시간보다 짧은 폭의 입력 변화는 좌변까지 전달되지 않을 수 있다.

6.1 event 처리 과정

  1. 우변 수식의 값을 평가한다.
  2. 새 평가값이 이미 예정된 할당값과 다르면 이전 예정 event를 취소한다.
  3. 새 값이 현재 좌변 값과 같으면 새로운 event를 예약하지 않는다.
  4. 새 값이 현재 좌변 값과 다르면 지연을 계산해 새로운 할당 event를 예약한다.
코드 4-4
module inertial_delay;

reg a, b;

assign #30 and_out = a & b;

initial begin
    a = 1'b0; b = 1'b0;

    #50 a = 1'b1; b = 1'b1;
    #50 a = 1'b0; b = 1'b0;
    #50 a = 1'b1; b = 1'b1;

    #20 b = 1'b0;

    #50 $finish;
end

endmodule

6.2 시간 흐름

t=150ns → a=1, b=1 → a & b = 1
20ns 후 → b=0 → a & b = 0
왜 출력이 1이 되지 않는가?
입력이 1을 유지한 시간은 20ns인데 assign #30의 지연은 30ns이다. 30ns가 지나기 전에 우변이 다시 0으로 바뀌어 기존 “1을 출력하라”는 예정 event가 취소되므로, 짧은 20ns 펄스는 출력에 나타나지 않는다.
Simulation과 실제 FPGA 구분
이 절의 #30은 시뮬레이션 모델에서의 지연 표현이다. 실제 FPGA의 지연은 합성·배치배선 후 Timing Analysis(타이밍 분석) 결과로 확인해야 한다.

7. 4.2 절차형 할당문

절차형 할당문은 reg, integer, real, time, realtime 등 variable의 값을 갱신한다. 할당된 값은 다음 절차형 할당에 의해 바뀔 때까지 유지된다.

절차형 할당문은 always, initial, task, function 등의 procedure 내부에서 사용하며, 시뮬레이션 실행 흐름이 해당 문장에 도달했을 때 할당이 일어난다.

7.1 연속 할당과 절차형 할당 비교

항목연속 할당문절차형 할당문
할당 대상 net variable
할당 기호 = blocking =, nonblocking <=
언제 갱신? 우변 수식 값의 event 발생 프로시저 실행 흐름이 문장에 도달했을 때
값 유지 구동자가 연속적으로 값을 결정 다음 할당까지 현재 값 유지
문장 순서 독립 연속 할당문의 순서는 결과에 영향 없음 블록 내부 순서가 결과에 영향을 줄 수 있음
사용 위치 모듈 내부 assign always, initial, task, function 내부
핵심 구분
연속 할당문은 “회로가 계속 net를 구동한다”는 의미이고, 절차형 할당문은 “프로시저 실행 순서에 따라 variable의 값이 갱신된다”는 의미이다.

8. blocking과 nonblocking 할당

절차형 할당문은 두 형태로 나뉜다.

blocking assignment

할당 기호 =

nonblocking assignment

할당 기호 <=

코드 4-5
module proc_assignment (
    input  clk,
    input  a,
    input  b,
    output out
);

reg out, c;

always @(posedge clk) begin
    c   = a & b;   // blocking assignment
    out <= c;      // nonblocking assignment
end

endmodule
posedge clk → c = a & b → out <= c
이 PDF의 설명 범위
이 장에서 두 할당 형식을 소개하고, blocking/nonblocking의 상세 동작은 다음 장인 행위수준 모델링에서 설명한다고 안내한다.

10. 4.3 절차형 연속 할당문(PCA)

절차형 연속 할당문(Procedural Continuous Assignment, PCA)은 일반적인 절차형 할당의 예외적인 형태로, procedure 내부에서 variable 또는 net을 계속 구동하도록 강제할 수 있다.

assign variable_lvalue = expression;
deassign variable_lvalue;

force variable_lvalue = expression;
force net_lvalue = expression;
release variable_lvalue;
release net_lvalue;
PCA대상해제 전 동작
assign-deassign variable 일반 절차형 할당을 덮어씀
force-release variable 절차형 할당 또는 PCA를 덮어씀
force-release net net, 게이트, 모듈 출력, 연속 할당 등 다른 구동자를 덮어씀

11. 4.3.1 assign-deassign 문

일반 assign 문은 net에 사용하는 연속 할당문이지만, assign PCA는 예외적으로 reg variable을 지속적으로 구동하여 기존 절차형 할당의 효과를 덮어쓴다. deassign이 실행되면 그 강제 구동 효과가 제거된다.

코드 4-7: assign-deassign PCA를 이용한 D 플립플롭
module dff_pca (
    input  clock,
    input  d,
    input  reset,
    input  set,
    output q
);

reg q;

always @(reset or set)
    if (!reset)
        assign q = 0;
    else if (!set)
        assign q = 1;
    else
        deassign q;

always @(posedge clock)
    q = d;

endmodule

11.1 동작 흐름

조건q 동작
reset = 0 assign q = 0이 q를 지속적으로 0으로 구동
set = 0 assign q = 1이 q를 지속적으로 1로 구동
reset = 1, set = 1 deassign q로 PCA 영향 제거 → clock 상승에지에서 d를 받음
reset/set 활성 → PCA assign이 q를 우선 구동 → clock 영향 차단
reset=set=1 → deassign → posedge clock에서 q=d

12. 4.3.2 force-release 문

force는 assign PCA보다 적용 범위가 넓으며, variable뿐 아니라 net에도 사용할 수 있다. release가 실행될 때까지 기존 구동을 덮어쓴다.

코드 4-8
module force_release;

reg a, b, c, out_and_reg;
wire out_and_g;

and AND_gate (out_and_g, a, b, c);

initial begin
    $monitor("%d out_and_reg=%b, out_and_g=%b",
             $stime, out_and_reg, out_and_g);

    assign out_and_reg = (a & b & c);

    a = 1;
    b = 0;
    c = 1;

    #10;

    force out_and_g   = (a | b | c);
    force out_and_reg = (a | b | c);

    #10;

    release out_and_g;
    release out_and_reg;

    #10 $finish;
end

endmodule

12.1 단계별 결과

시간상태out_and_regout_and_g
0 원래 AND 구동 0 0
10 force로 OR 결과 강제 1 1
20 release로 원래 구동 복귀 0 0
원래 AND 결과 force OR 결과로 강제 덮어쓰기 release 원래 구동자 결과로 복귀
사용 관점
이 절의 force/release는 회로의 정상적인 데이터패스를 기술하기보다는 시뮬레이션에서 신호를 강제로 덮어쓰거나 특정 상태를 검증할 때 이해하는 것이 중요하다. PCA를 일반 절차형 할당과 구분되는 예외적인 구문으로 설명한다.

13. 최종 핵심 정리

구문좌변언제 값이 바뀌는가핵심 의미
assign y = expr; net 우변 값 변화 조합논리의 연속 구동
blocking = variable 프로시저 실행이 해당 문장에 도달 절차형 할당
nonblocking <= variable 프로시저 실행에 의해 예약·갱신 절차형 할당
assign-deassign PCA variable assign PCA 실행 후 deassign까지 절차형 할당을 덮어씀
force-release variable / net force 실행 후 release까지 기존 구동자를 강제로 덮어씀
이 장핵심 질문
할당문을 볼 때는 먼저 “좌변이 net인가 variable인가?”, “값은 우변 변화 때문에 자동 갱신되는가, 문장 실행 때문에 갱신되는가?”, “이 할당은 지속 구동인가, 특정 시점의 값 갱신인가?”를 구분해야 한다.
연속 할당 → net 구동 → 조합회로
절차형 할당 → variable 갱신 → always / initial 흐름
PCA → 기존 할당·구동 덮어쓰기 → deassign / release로 해제
