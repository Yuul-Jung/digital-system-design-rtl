1. CHAPTER 05 전체 개요

앞 장의 게이트 프리미티브, 연속 할당문, 구조적 모델링은 회로의 구조를 직접 표현하는 성격이 강하다. 반면 행위수준 모델링(behavioral modeling, 비헤이비어럴 모델링)은 회로가 “어떻게 동작해야 하는가”를 조건, 이벤트, 반복, 순차적 문장으로 표현한다.

조합회로

always @(*), if, case 등을 사용해 입력 조건과 출력 동작을 기술한다.

순차회로

always @(posedge clk)처럼 클록 에지에서 상태를 갱신한다.

테스트벤치

initial, forever, #delay, event 등을 이용해 파형과 검증 시나리오를 만든다.

가장 중요한 구분
모듈 내부의 여러 always/initial 블록은 서로 독립적으로 병렬 동작한다. 그러나 각 블록 내부의 절차형 문장은 blocking/nonblocking의 규칙과 문장 순서에 따라 실행 결과가 달라질 수 있다.
RTL 해석 보강
Verilog를 C 언어처럼 소스 전체가 위에서 아래로 한 줄씩 실행된다고 보면 안 된다. 하드웨어에서는 여러 always 블록이 동시에 존재하며, 클록·입력·이벤트가 조건을 만족하는 순간 각 블록이 독립적으로 활성화된다.

1.1 이 장의 전체 흐름

always / initial → 절차형 할당 → if / case → 반복문 → 타이밍 제어 → begin-end / fork-join

2. 5.1 always 구문과 initial 구문

2.1 always 구문

always는 행위수준 모델링의 대표적인 구문이다. 조합회로, 순차회로, 테스트벤치에 폭넓게 사용할 수 있으며 시뮬레이션 동안 반복적으로 실행되는 구조라고 설명한다.

always [@(sensitivity_list)] begin blocking_or_nonblocking statements; end
  • @(...) 안에는 블록 실행을 트리거할 감지신호목록(sensitivity list)이 들어간다.
  • 감지신호에 event가 발생하면 begin-end 내부 문장이 실행된다.
  • 블록 내부는 절차형 문장들로 구성된다.
  • blocking/nonblocking의 선택에 따라 시뮬레이션과 합성 의미가 달라질 수 있다.

2.2 조합회로 예 — 2입력 OR

코드 5-1
module or2 (
    input  a,
    input  b,
    output out
);

reg out;

always @(a or b) begin
    if (a == 1'b1 || b == 1'b1)
        out = 1'b1;
    else
        out = 1'b0;
end

endmodule
a,b 변화 →
always 실행
→
if 판단
→ out 갱신
합성 후 회로
이 코드는 상태를 저장하지 않는다. 입력 a, b가 바뀔 때마다 출력이 다시 계산되므로 실제 합성 결과는 2입력 OR 조합논리에 대응한다.

2.3 순차회로 예 — D 플립플롭

코드 5-2
module dff (
    input  clk,
    input  din,
    output qout
);

reg qout;

always @(posedge clk)
    qout <= din;

endmodule
현재 din → posedge clk → qout 레지스터 저장
Clock 기준 해석
din이 아무리 많이 변해도 clk 상승에지가 오기 전에는 qout이 갱신되지 않는다. 즉, 코드핵심은 “값”보다 언제 저장되는가이다.

3. 조합회로와 감지신호목록

조합회로를 always 블록으로 기술할 때는 블록 내부에서 참조되는 모든 입력이 감지신호목록에 들어가야 한다. 일부 입력이 빠지면 RTL 시뮬레이션에서 해당 신호 변화가 블록 실행을 트리거하지 않아 의도한 조합회로와 다른 파형이 나올 수 있다.

코드 5-3: sel이 감지신호목록에서 빠진 경우
module mux21_omit_sel (
    input  [1:0] a,
    input  [1:0] b,
    input        sel,
    output [1:0] out
);

reg [1:0] out;

always @(a or b) begin   // sel이 없음
    if (sel == 1'b0)
        out = a;
    else
        out = b;
end

endmodule
문제점
sel만 바뀌고 a, b는 그대로라면 always가 다시 실행되지 않는다. 따라서 RTL 시뮬레이션에서 출력이 즉시 바뀌지 않는다. 이 경우 합성 전 RTL 시뮬레이션과 합성 후 결과가 달라질 수 있음을 지적한다.

3.1 @(*) 사용

always @(*) begin
    y = (a & b) | (c & d);
end

@(*) 또는 @*는 블록에서 읽는 관련 신호들을 감지신호목록에 자동으로 포함시키는 함축적 표현이다.

조합회로 기본 습관
전통 Verilog에서 조합회로를 always로 기술할 때는 수동 감지신호 목록보다 always @(*)를 사용하는 편이 누락 위험을 줄이는 데 유리하다.

4. zero-delay 무한루프와 initial 구문

4.1 zero-delay infinite loop

always clk = ~clk;

위 코드는 시간 진행을 일으키는 지연이나 이벤트 제어가 없다. 따라서 같은 시뮬레이션 시간에서 무한히 반복되어 시뮬레이션이 진행되지 않는 zero-delay 무한루프가 발생한다.

4.2 20ns 주기의 클록 생성

코드 5-4
module clk_gen;

reg clk;

initial
    clk = 1'b0;

always
    #10 clk = ~clk;

endmodule
clk=0 10ns clk=1 10ns clk=0 → 주기 20ns
왜 초기화가 필요한가?
reg의 시뮬레이션 초기값은 기본적으로 x이다. ~x 역시 x이므로, 초기화하지 않으면 클록이 계속 unknown 상태를 유지할 수 있다.

4.3 initial 구문

initial begin blocking_or_nonblocking statements; end

initial을 시뮬레이션 동안 한 번 실행되는 구문으로 설명하며, 테스트벤치에서 초기화와 입력 파형 생성에 사용한다.

예시 5-3: 초기화
initial begin
    areg = 0;

    for (index = 0; index < size; index = index + 1)
        memory[index] = 0;
end
예시 5-4: 입력 벡터 생성
initial begin
    din = 6'b000000;
    #10 din = 6'b011001;
    #10 din = 6'b011011;
    #10 din = 6'b011000;
    #10 din = 6'b001000;
end
initial은 테스트벤치의 초기화와 입력 파형 생성에 사용하는 시뮬레이션 구문으로 다룬다.

4.4 서로 다른 주기의 두 신호

코드 5-5
module periodic_sig_gen;

reg a, b;

initial begin
    a = 1'b1;
    b = 1'b0;
end

always
    #50 a = ~a;

always
    #100 b = ~b;

endmodule
신호초기값반전 간격주기
a150ns100ns
b0100ns200ns
병렬성
하나의 initial과 두 개의 always 블록은 시뮬레이션 시작 시 서로 독립적으로 활성화된다. 코드에 위아래로 적혀 있어도 세 블록이 순차적으로 “호출”되는 것이 아니다.

5. 5.2 절차형 할당문

절차형 할당문은 reg, integer, time, real, realtime과 같은 variable의 값을 갱신한다.

연속 할당절차형 할당
우변 값 변화가 발생하면 net을 계속 구동 프로시저 실행 흐름이 해당 문장에 도달했을 때 variable 갱신
하드웨어적 연속 구동 특성 블록 내부에서는 문장 실행 순서가 의미를 가짐
assign blocking =, nonblocking <=

5.1 절차형 할당의 대상

  • variable 전체
  • 단일 비트
  • 연속된 일부 비트(part select)
  • 메모리의 단일 word
  • 결합(concatenation)에 의한 여러 좌변
우변 비트 수가 좌변보다 작고 우변이 signed이면, 좌변 폭에 맞춰 sign extension(부호 확장)이 이루어진다고 설명한다.

6. 5.2.1 blocking 할당문

blocking 할당은 현재 문장의 실행이 끝난 뒤 다음 문장으로 넘어가는 순차적 실행 흐름을 갖는다. 할당 기호는 =이다.

reg_lvalue = [delay_or_event_control] expression;
예시 5-5
initial begin
    rega = 0;
    regb[3] = 1;
    regc[3:5] = 7;
    mema[address] = 8'hff;
    {carry, acc} = rega + regb;
end
문장 1 완료 → 문장 2 완료 → 문장 3 완료 → ...

7. 5.2.2 nonblocking 할당문

nonblocking 할당은 우변을 평가한 뒤 좌변 갱신을 스케줄하며, 현재 문장의 좌변 갱신이 끝날 때까지 다음 문장을 막지 않는다. 할당 기호는 <=이다.

reg_lvalue <= [delay_or_event_control] expression;
순차회로에서 중요한 이유
여러 레지스터가 같은 클록 에지에서 동시에 이전 값을 샘플링하는 동작을 자연스럽게 표현할 수 있다. 시프트 레지스터처럼 각 단계가 이전 단계의 “클록 직전 값”을 받아야 하는 회로에 특히 중요하다.

7.1 blocking과 nonblocking 비교

코드 5-6(a): blocking
module blk;

reg clk, a, b;

initial begin
    a = 0;
    b = 1;
    clk = 0;
end

always
    clk = #5 ~clk;

always @(posedge clk) begin
    a = b;
    b = a;
end

endmodule
클록 직전 a=0, b=1 → a=b 실행 → a=1 → b=a 실행 → b=1 → 최종 a=1,b=1
코드 5-6(b): nonblocking
module non_blk;

reg clk, a, b;

initial begin
    a = 0;
    b = 1;
    clk = 0;
end

always
    clk = #5 ~clk;

always @(posedge clk) begin
    a <= b;
    b <= a;
end

endmodule
1단계 — 우변 평가
클록 에지 직전 값 a=0, b=1을 사용하므로 a에 예약되는 값은 1, b에 예약되는 값은 0이다.
2단계 — 좌변 갱신
스케줄된 갱신이 적용되면서 최종적으로 a=1, b=0이 된다.
회로 구조로 보면
nonblocking 예는 두 레지스터가 같은 클록 에지에서 서로의 이전 값을 교환하는 구조와 대응한다. 반면 blocking 예는 첫 번째 할당으로 바뀐 값이 두 번째 문장에 즉시 사용되므로 시뮬레이션 동작이 다르다.

7.2 지연이 포함된 blocking / nonblocking

코드 5-7
module blk_nonblk_delay;

reg blk_a, blk_b, blk_c;
reg nblk_a, nblk_b, nblk_c;

initial begin
    blk_a = #15 1'b1;
    blk_b = #5  1'b0;
    blk_c = #10 1'b1;
    #50 $finish;
end

initial begin
    nblk_a <= #15 1'b1;
    nblk_b <= #5  1'b0;
    nblk_c <= #10 1'b1;
    #50 $finish;
end

endmodule
형태값이 반영되는 시각이유
blocking blk_a: 15ns, blk_b: 20ns, blk_c: 30ns 각 문장이 이전 문장 완료 뒤 시작되므로 지연이 누적
nonblocking nblk_b: 5ns, nblk_c: 10ns, nblk_a: 15ns 우변 평가 뒤 각각의 갱신 시점이 독립적으로 예약

7.3 동일 변수에 여러 nonblocking 할당

코드 5-8
module multiple_nblk;

reg a;

initial
    a = 1'b1;

initial begin
    a <= #5 1'b1;
    a <= #5 1'b0;

    #20 $stop;
end

endmodule

두 문장이 동일한 지연 #5를 가지므로 같은 시각에 같은 변수로 두 갱신이 예약되며, 문장 순서에 의해 최종적으로 a=0이 된다고 설명한다.

8. 5.3 if 조건문

if (expression) statement_true; else statement_false;

조건이 0이 아닌 알려진 값이면 참으로, 0 또는 x/z이면 거짓 쪽으로 처리된다. else는 생략할 수 있다.

조합회로에서 else 생략 주의
조합회로를 모델링하면서 어떤 조건에서 출력에 값이 할당되지 않으면 이전 값을 유지해야 하므로 latch(래치)가 합성될 수 있다.

8.1 nested if와 dangling else

if (index > 0)
    if (rega > regb)
        result = rega;
    else
        result = regb;

else는 일반적으로 가장 가까운 앞의 if와 결합된다. 첫 번째 if와 묶으려면 begin-end를 사용해 범위를 명확히 한다. 

if (index > 0) begin
    if (rega > regb)
        result = rega;
end
else
    result = regb;

8.2 if-else-if

if (expression1)
    statement1;
else if (expression2)
    statement2;
else
    default_statement;

조건을 위에서부터 순서대로 평가하며, 처음으로 참이 되는 조건의 문장을 실행한다.

8.3 2:1 멀티플렉서

코드 5-9
module mux21_if (
    input  [1:0] a,
    input  [1:0] b,
    input        sel,
    output [1:0] out
);

reg [1:0] out;

always @(a or b or sel) begin
    if (sel == 1'b0)
        out = a;
    else
        out = b;
end

endmodule
a ↘
2:1 MUX
sel
→ out ↗ b

8.4 비동기 active-low set/reset D 플립플롭

코드 5-10
module dff_async_sr (
    input  clk,
    input  d,
    input  rb,
    input  sb,
    output q,
    output qb
);

reg q;

always @(posedge clk or negedge rb or negedge sb) begin
    if (rb == 0)
        q <= 0;
    else if (sb == 0)
        q <= 1;
    else
        q <= d;
end

assign qb = ~q;

endmodule
이벤트/조건q 동작
rb가 0클록과 무관하게 q를 0으로 reset
sb가 0클록과 무관하게 q를 1로 set
rb=1, sb=1, posedge clkd를 q에 저장
왜 reset/set을 감지신호목록에 넣는가?
비동기 신호는 클록 에지를 기다리지 않고 즉시 q를 바꿔야 하므로 negedge rb, negedge sb 자체가 블록 실행 조건이 되어야 한다.

9. 5.4 case 문

case (expression) case_item : statement; ... default : statement; endcase

case는 하나의 조건식과 여러 case item을 비교하여 일치하는 항의 문장을 실행한다. 일치 항이 없고 default가 없으면 해당 variable은 이전 값을 유지할 수 있다.

코드 5-11: case를 이용한 2:1 MUX
module mux21_case (
    input  [1:0] a,
    input  [1:0] b,
    input        sel,
    output [1:0] out
);

reg [1:0] out;

always @(a or b or sel) begin
    case (sel)
        0: out = a;
        1: out = b;
    endcase
end

endmodule
default가 없는 조합회로
모든 가능한 입력 조건이 case item에 포함되지 않으면 출력이 어떤 조건에서 할당되지 않아 이전 값을 유지할 수 있으므로 래치 추론 가능성을 검토해야 한다.

9.1 8비트 입력에 따른 10비트 출력

예시 5-9
wire [7:0] din;
reg  [9:0] result;

always @(din) begin
    case (din)
        8'd0: result = 10'b0111111111;
        8'd1: result = 10'b1011111111;
        8'd2: result = 10'b1101111111;
        8'd3: result = 10'b1110111111;
        8'd4: result = 10'b1111011111;
        8'd5: result = 10'b1111101111;
        8'd6: result = 10'b1111110111;
        8'd7: result = 10'b1111111011;
        8'd8: result = 10'b1111111101;
        8'd9: result = 10'b1111111110;
        default: result = 10'bx;
    endcase
end

9.2 x와 z의 정확한 비교

기본 case는 0, 1뿐 아니라 x, z도 비트 단위로 정확히 일치해야 같은 항으로 판단한다.

예시 5-10
case (select[2:1])
    2'b00: result = 0;
    2'b01: result = flaga;

    2'b0x, 2'b0z:
        result = flaga ? 'bx : 0;

    2'b10: result = flagb;

    2'bx0, 2'bz0:
        result = flagb ? 'bx : 0;

    default:
        result = 'bx;
endcase
예시 5-11: x/z 검출
case (sig)
    1'bz:    $display("signal is floating");
    1'bx:    $display("signal is unknown");
    default: $display("signal is %b", sig);
endcase

10. 5.4.1 don’t-care를 갖는 case 문

구문don’t-care 처리
casezz를 don’t-care로 취급
casexx와 z를 don’t-care로 취급

casez에서는 ?도 don’t-care 비트로 사용할 수 있다.

10.1 casez 명령어 디코더 형태

예시 5-12
reg [7:0] ir;

casez (ir)
    8'b1???_????: instruction1(ir);
    8'b01??_????: instruction2(ir);
    8'b0001_0???: instruction3(ir);
    8'b0000_01??: instruction4(ir);
endcase

MSB 쪽에서 먼저 1이 나타나는 위치에 따라 서로 다른 명령 처리 task를 선택하는 구조이다.

10.2 casex 우선순위 인코더

코드 5-12
module pri_enc_casex (
    input  [3:0] encode,
    output [1:0] enc
);

reg [1:0] enc;

always @(encode) begin
    casex (encode)
        4'b1xxx: enc = 2'b11;
        4'b01xx: enc = 2'b10;
        4'b001x: enc = 2'b01;
        4'b0001: enc = 2'b00;
    endcase
end

endmodule
회로 구조
encode[3]이 1이면 나머지 비트를 보지 않고 3을 선택하고, 그렇지 않으면 bit 2, bit 1, bit 0 순으로 검사한다. 즉, 상위 비트가 더 높은 우선순위를 갖는 priority encoder(우선순위 인코더)이다.

10.3 case(1) 형태의 우선순위 인코더

코드 5-13
module pri_enc_case (
    input  [3:0] encode,
    output [1:0] enc
);

reg [1:0] enc;

always @(encode) begin
    case (1)
        encode[3]: enc = 2'b11;
        encode[2]: enc = 2'b10;
        encode[1]: enc = 2'b01;
        encode[0]: enc = 2'b00;
        default:
            $display("Error: One of the bits expected ON");
    endcase
end

endmodule

11. 5.5 반복문

반복문동작합성 관점
forever무한 반복테스트벤치 전용으로 설명
repeat(N)N회 반복반복 횟수가 결정됨
while조건이 참인 동안 반복반복 횟수가 불명확하면 합성 실패 가능
for초기화-조건-갱신 구조고정 반복 구조에 적합
합성 관점 보강
RTL의 반복문은 소프트웨어처럼 동일한 하드웨어가 시간에 따라 반복 실행된다는 뜻이 아닐 수 있다. 조합회로 블록에서 반복 횟수가 정적으로 결정되면 합성기는 반복문을 여러 단계의 하드웨어로 전개(unroll)할 수 있다.

11.1 repeat를 이용한 shift-add 곱셈기

코드 5-14
module multiplier_8b #(
    parameter SIZE = 8,
    parameter LongSize = 2*SIZE
)(
    input  [SIZE-1:0] opa,
    input  [SIZE-1:0] opb,
    output [LongSize-1:0] result
);

reg [LongSize-1:0] result;
reg [LongSize-1:0] shift_opa;
reg [LongSize-1:0] shift_opb;

always @(opa or opb) begin
    shift_opa = opa;
    shift_opb = opb;
    result = 0;

    repeat (SIZE) begin
        if (shift_opb[0])
            result = result + shift_opa;

        shift_opa = shift_opa << 1;
        shift_opb = shift_opb >> 1;
    end
end

endmodule

알고리즘 흐름

승수 LSB 확인 → 1이면 부분곱 가산 → 피승수 << 1 → 승수 >> 1 → SIZE회 반복
중요한 회로 해석
이 예는 클록이 없는 always 블록 안에서 repeat를 수행한다. 따라서 “8클록에 걸쳐 계산”하는 순차 곱셈기로 자동 해석하면 안 된다. 합성 시에는 반복 단계들이 조합논리 경로로 전개될 가능성을 고려해야 하며, 실제 구조와 타이밍은 합성 결과에서 확인해야 한다.

11.2 while을 이용한 1의 개수 계수

코드 5-15
module count_ones (
    input  [7:0] din,
    output [3:0] count
);

reg [3:0] count;
reg [7:0] temp;

always @(din) begin
    count = 0;
    temp  = din;

    while (temp) begin
        if (temp[0])
            count = count + 1;

        temp = temp >> 1;
    end
end

endmodule

temp를 오른쪽으로 한 비트씩 이동하면서 LSB가 1일 때 count를 증가시킨다.

Vivado 합성 예
이 형태가 반복 횟수를 합성 시점에 명확히 확정하기 어려워 Vivado에서 loop convergence 오류로 합성 실패할 수 있다고 설명한다.

11.3 반복 횟수를 명확히 한 형태

코드 5-16
module count_ones_syn (
    input  [7:0] din,
    output [3:0] count
);

reg [3:0] count, k;
reg [7:0] temp;

always @(din) begin
    count = 0;
    temp  = din;
    k     = 0;

    while (k < 8) begin
        if (temp[0])
            count = count + 1;

        temp = temp >> 1;
        k = k + 1;
    end
end

endmodule

11.4 for 우선순위 인코더

코드 5-17
module pri_enc_for (
    input  [7:0] din,
    output [2:0] enc_out
);

reg [2:0] enc_out;
integer i;

always @(din) begin : LOOP
    enc_out = 0;

    for (i = 7; i >= 0; i = i - 1) begin
        if (din[i]) begin
            enc_out = i;
            disable LOOP;
        end
    end
end

endmodule

MSB부터 검사하여 처음 발견되는 1의 위치를 출력하고, disable LOOP으로 현재 named block을 종료한다.

11.5 forever를 이용한 테스트벤치 파형

코드 5-18
module tb_dff;

reg clk, din;

dff U1 (clk, din, q);

initial begin
    clk = 1'b0;

    forever
        #10 clk = ~clk;
end

initial begin
    din = 1'b0;

    forever begin
        #15 din = 1'b1;
        #20 din = 1'b0;
        #30 din = 1'b1;
        #20 din = 1'b0;
    end
end

endmodule
신호특징
clk10ns마다 반전 → 주기 20ns
din15 + 20 + 30 + 20 = 85ns 패턴 반복

12. 5.6 절차형 할당의 타이밍 제어

절차형 문장 실행을 제어하는 방법으로 지연 제어(#), 이벤트 제어(@), wait를 설명한다.

# delay

지정한 시간만큼 실행을 지연

@ event

특정 값 변화 또는 에지를 기다림

wait()

조건이 특정 level을 만족할 때까지 기다림

12.1 지연 제어

#10 rega = regb;

#d rega = regb;

#((d + e) / 2)
rega = regb;

#은 해당 문장의 실행을 지정 시간만큼 늦춘다. parameter나 수식으로 지연값을 표현할 수도 있다고 설명한다.

12.2 이벤트 제어

@event_identifier @(event_expression) @* @(*)

이벤트 식에는 여러 신호를 or 또는 콤마로 연결할 수 있고, posedge, negedge로 에지 방향을 지정할 수 있다.

12.3 posedge / negedge

변화이벤트
0 → 1posedge
0 → x / zposedge
x / z → 1posedge
1 → 0negedge
1 → x / znegedge
x / z → 0negedge
코드 5-19
module dff (
    input  clk,
    input  din,
    output qout
);

reg qout;

always @(posedge clk)
    qout <= din;

endmodule
플립플롭 감지신호목록
일반 D 플립플롭에서는 데이터 입력 din이 아니라 클록 에지 posedge clk가 저장 이벤트이다. 비동기 reset/set이 있다면 그 비동기 신호의 에지도 함께 감지해야 한다.

13. 5.6.3 named event와 event or

Verilog의 event 자료형으로 선언된 named event는 데이터 값을 저장하지 않고 “사건이 발생했다”는 순간적 트리거를 표현한다.

event event_name; -> event_name;
합성 범위
이벤트 트리거가 Vivado에서 합성되지 않는다고 설명한다. 따라서 이 부분은 주로 시뮬레이션 프로세스 간 동기화 관점으로 이해한다.

13.1 named event를 이용한 D 플립플롭 형태

코드 5-20
module dff_event (
    input  clock,
    input  reset,
    input  din,
    output qout
);

reg qout;
event upedge;

always @(posedge clock)
    -> upedge;

always @(upedge or negedge reset) begin
    if (reset == 0)
        qout = 0;
    else
        qout = din;
end

endmodule
posedge clock → upedge 트리거 → 두 번째 always 실행

13.2 count가 5의 배수일 때 event 발생

코드 5-21
module named_event;

reg [7:0] count;
event ready;

initial begin
    count = 0;
    #400 $finish;
end

always begin
    #2 count <= count + 1;

    if (count % 5 == 0)
        -> ready;
end

always @(ready) begin
    $display($realtime, "The count is %d", count);
end

endmodule

13.3 event or와 콤마

always @(posedge clk_a or posedge clk_b or trig)
    rega = regb;

always @(posedge clk_a, posedge clk_b, trig)
    rega = regb;

위 두 표현을 같은 의미로 설명한다.

14. 5.6.5 wait와 5.6.6 intra-assignment 타이밍 제어

14.1 wait

wait (expression) statement;

wait는 조건이 참이 될 때까지 실행을 멈추며, 이를 level-sensitive 이벤트 제어로 설명한다.

예시 5-15
begin
    wait (!enable)
        #10 a = b;

    #10 c = d;
end
enable=0 기다림 → 10ns → a=b → 10ns → c=d

14.2 일반 지연과 intra-assignment 지연의 차이

문장 앞 지연 
#5 q = b;

5시간 단위를 기다린 뒤 b를 평가하고 q에 할당한다.

intra-assignment 
q = #5 b;

b를 먼저 평가해 보관하고, 5시간 단위 후 그 저장값을 q에 할당한다.

14.3 fork-join의 race와 data swap

예시 5-16
fork
    #5 a = b;
    #5 b = a;
join

두 문장이 병렬로 같은 시각에 실행되므로 상호 참조 순서에 따라 race condition(경쟁상태)이 발생할 수 있다.

예시 5-17: intra-assignment를 이용한 swap
fork
    a = #5 b;
    b = #5 a;
join
동작
두 문장 모두 현재 a, b 값을 먼저 읽어 임시 보관한 뒤 5시간 단위 후 서로 반대 좌변에 기록한다. 즉, 평가 시점과 갱신 시점을 분리한다.

14.4 이벤트 기반 intra-assignment

예시 5-18
fork
    a = @(posedge clk) b;
    b = @(posedge clk) c;
join

우변 값은 문장을 만났을 때 평가되고, posedge clk 이벤트까지 보관된 뒤 좌변에 할당된다.

14.5 repeat 이벤트 제어

예시 5-19
q <= repeat(5) @(posedge clk) data;
data 먼저 평가 → clk 상승에지 1 → 2 → 3 → 4 → 5 → q 갱신
예시 5-20
q = repeat(num) @(clk) data;
예시 5-21
q <= repeat(a+b) @(posedge phi1 or negedge phi2) data;

14.6 등가 표현

intra-assignment의미를 풀어쓴 형태
q = #5 b; temp=b; → 5만큼 기다림 → q=temp;
q = @(posedge clk) b; temp=b; → clk 상승에지 기다림 → q=temp;
q = repeat(3) @(posedge clk) b; temp=b; → 상승에지 3회 대기 → q=temp;

14.7 3번째 상승에지 후 처음 평가한 d를 출력

코드 5-22
module intra_assign_delay (
    input  clk,
    input  d,
    output out
);

reg out;

always @(*)
    out = repeat(3) @(posedge clk) d;

endmodule
코드 5-23: 풀어쓴 등가 코드
module intra_assign_delay_eq (
    input  clk,
    input  d,
    output out
);

reg out, temp;

always @(*) begin
    temp = d;

    @(posedge clk);
    @(posedge clk);
    @(posedge clk);

    out = temp;
end

endmodule
핵심
세 번째 클록 에지에서 그 시점의 d를 읽는 것이 아니라, 문장을 처음 만났을 때 읽어 둔 d 값을 세 번의 이벤트 후에 출력한다.

15. 5.7 블록문

Verilog는 여러 문장을 하나의 문장처럼 그룹화하기 위해 begin-end 절차형 블록과 fork-join 병렬 블록을 제공한다.

블록실행 방식지연 기준종료 시점
begin-end 문장 순서대로 순차 실행 앞 문장 완료 시각을 기준으로 누적 마지막 문장 완료
fork-join 모든 문장 동시 시작 블록 진입 시각을 공통 기준으로 사용 가장 늦게 끝나는 문장 완료

15.1 named block

begin : block_name declarations; statements; end

블록 이름을 붙이면 지역 변수, parameter, named event를 선언하거나 disable 문에서 해당 블록을 참조할 수 있다.

15.2 begin-end 절차형 블록

예시 5-22
begin
    areg = breg;
    creg = areg;
end
areg=breg 완료 후 creg=areg
예시 5-23: 이벤트가 포함된 순차 블록
begin
    areg = breg;
    @(posedge clock)
        creg = areg;
end

15.3 순차 지연으로 파형 생성

코드 5-24
parameter d = 50;

reg [7:0] r;
event end_wave;

initial begin
    #d r = 8'h35;
    #d r = 8'hE2;
    #d r = 8'h00;
    #d r = 8'hF7;
    #d -> end_wave;
end
시간동작
50r=8'h35
100r=8'hE2
150r=8'h00
200r=8'hF7
250end_wave event 발생

15.4 fork-join 병렬 블록

fork statement1; statement2; ... join
코드 5-25(a)
fork
    #50  r = 8'h35;
    #100 r = 8'hE2;
    #150 r = 8'h00;
    #200 r = 8'hF7;
    #250 -> end_wave;
join
코드 5-25(b): 순서가 뒤집혀도 동일 파형
fork
    #250 -> end_wave;
    #200 r = 8'hF7;
    #150 r = 8'h00;
    #100 r = 8'hE2;
    #50  r = 8'h35;
join
왜 결과가 같은가?
fork 내부 각 문장은 블록 진입 시각을 기준으로 동시에 시작한다. 따라서 소스에서 위아래 순서를 바꿔도 각 문장의 지연값이 같다면 동일한 시각에 동일한 동작이 발생한다.

15.5 fork 안에 두 개의 begin-end 블록

코드 5-26
fork
    @(enable_a) begin
        #ta wa = 0;
        #ta wa = 1;
        #ta wa = 0;
    end

    @(enable_b) begin
        #tb wb = 1;
        #tb wb = 0;
        #tb wb = 1;
    end
join
enable_a 이벤트 → wa 파형 생성 블록
enable_b 이벤트 → wb 파형 생성 블록

두 이벤트 대기는 fork 내부에서 병렬로 이루어지고, 각 이벤트가 발생하면 해당 begin-end 블록은 내부적으로 순차 실행된다.

Digital Design → Verilog RTL → Synthesis 연결
조합논리는 입력 변화에 따라 계산되고, 순차논리는 클록 에지에서 레지스터에 저장된다. if, case는 선택 논리와 제어 논리로, 산술식은 연산 회로로, 클록 에지 기반 nonblocking 할당은 플립플롭/레지스터 구조로 연결된다. 반면 #delay, named event, 많은 테스트벤치 제어 구문은 시뮬레이션을 위한 표현이므로 실제 FPGA의 물리적 지연과 구분해야 한다.
입력 / 이벤트 / Clock → always / initial 활성화 → if / case / loop → blocking / nonblocking 갱신 → 조합회로 또는 레지스터 구조
