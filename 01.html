1. 전체 개요

Verilog HDL(베릴로그 HDL, 하드웨어 기술 언어)의 소스 코드는 여러 종류의 어휘 토큰(lexical token, 렉시컬 토큰)으로 구성된다. 이 절에서는 소스 코드에서 가장 기본이 되는 표현 규칙을 다룬다.

여백→ 주석→ 연산자→ 수→ 문자열→ 식별자→ 키워드
핵심 관점
Verilog 코드를 읽을 때 먼저 “문자가 어떤 토큰으로 분해되는가”를 이해하면, 수의 비트 폭, 부호, 문자열의 저장 방식, 이름 규칙, 시뮬레이션용 명령과 합성용 속성을 훨씬 정확하게 해석할 수 있다.

2. 여백과 주석

2.1 여백(white space)

빈칸(space), 탭(tab), 줄바꿈 등은 토큰을 서로 구분하기 위해 사용되는 경우를 제외하면 일반적으로 무시된다. 단, 문자열 안의 공백과 탭은 실제 데이터이므로 의미가 있다.

2.2 주석(comment)

형식범위특징
// ...현재 위치부터 줄 끝까지단일 라인 주석
/* ... */시작 기호부터 종료 기호까지블록 주석. 블록 주석 내부에 또 다른 블록 주석을 중첩할 수 없음
 
// 한 줄 주석

/* 여러 줄에 걸쳐
   작성할 수 있는
   블록 주석 */
읽기 포인트
//는 블록 주석 내부에서는 별도의 주석 시작 기호로 처리되지 않는다. 이미 /* ... */ 범위 전체가 주석이기 때문이다.

3. 수 표현

Verilog HDL의 상수 값은 크게 정수형(integer)과 실수형(real)으로 구분된다. 정수형 상수는 2진수, 8진수, 10진수, 16진수로 표현할 수 있다.

3.1 기본 형식

[size_constant]'[s]base_format number_value
구성의미
size_constant상수의 비트 수. 0이 아닌 unsigned 10진수 사용. 생략하면 unsized 상수
s선택적인 signed 지정자. 비트 패턴 자체를 바꾸는 것이 아니라 그 패턴의 해석 방식에 영향을 줌
base_formatb/B: 2진수, o/O: 8진수, d/D: 10진수, h/H: 16진수
number_value지정한 밑수에 맞는 숫자 값
2진수
8'b1010_0011
8진수
12'o735
10진수
8'd25
16진수
16'hABCD
문법상 중요
인용부호(')와 밑수 지정 문자는 붙여 쓴다. 밑수 지정 문자와 실제 숫자 값 사이에 +, -를 넣을 수 없으며, 부호를 사용할 때는 상수 전체 앞에 둔다.

3.2 Unsized 상수 예

예시 1-1
659       // 단순 10진수 표현
'h837FF   // size가 생략된 16진수
'o7460    // size가 생략된 8진수
4af       // 문법 오류: 16진수라면 'h가 필요하고, 10진수에는 a, f를 사용할 수 없음

비트 크기와 밑수 지정이 없는 단순 10진수를 signed 정수로 설명하며, 밑수만 지정하면 unsigned, s와 밑수를 함께 지정하면 signed로 취급된다고 설명한다.

3.3 Sized 상수 예

예시 1-2
4'b1001   // 4비트 2진수 1001
5'D3      // 5비트 10진수 3
3'b01x    // LSB가 x인 3비트 01x
12'hx     // 12비트의 x
16'hz     // 16비트의 z
특수 값의미
xunknown(언노운, 알 수 없는 값)
zhigh-impedance(하이 임피던스, 고임피던스 상태)

3.4 부호와 2의 보수

예시 1-3
8'd-6     // 문법 오류: d와 값 사이에 부호를 넣을 수 없음
-8'd6     // -(8'd6), 즉 -6

4'shf     // 4비트 1111을 signed로 해석
           // 2의 보수 기준 10진수 -1

-4'sd15   // 4비트 signed 값에 단항 - 적용

-'d12     // 밑수만 지정 → unsigned 해석
-'sd12    // s와 밑수 지정 → signed 해석
핵심 이해
s는 비트 패턴을 바꾸는 기호가 아니다. 동일한 비트열이라도 signed인지 unsigned인지에 따라 수치 해석이 달라진다. 음수는 2의 보수(two's complement, 투스 컴플리먼트) 형식으로 표현된다.

3.5 밑줄을 이용한 가독성 향상

예시 1-4
27_195_000
16'b0011_0101_0001_1111
32'h12ab_f001

밑줄(_)은 값을 바꾸지 않으며, 긴 숫자를 읽기 쉽게 구분하기 위한 용도로 사용할 수 있다.

3.6 지정된 비트 폭과 자동 확장

예시 1-5
reg [11:0] a, b, c, d;

initial begin
    a = 'hx;    // 상위 쪽에 x가 확장
    b = 'h3x;   // 상위 쪽에 0이 확장
    c = 'hz3;   // 상위 쪽에 z가 확장
    d = 'h0z3;  // 지정된 값 그대로 할당
end

지정된 비트 수보다 값의 자릿수가 작을 때 상위 비트 쪽에 0, x, z가 상황에 맞게 채워지는 동작을 설명한다.

3.7 실수형 상수

실수형 상수는 10진 실수 또는 과학 표기법으로 표현한다. 지수는 e 또는 E를 사용할 수 있다. 소수점을 사용할 때는 소수점 좌우에 숫자가 있어야 한다.

예시 1-6: 유효한 실수형 표현
1.2
2394.26331
1.2E12
1.30e-2
0.1e-0
29E-2
236.123_763_e-12
예시 1-7: 문법 오류
.12
9.
4.E3
.2e-7
정수 객체에 실수 값을 넣을 때
실수 값이 정수형 객체에 할당되면 가장 가까운 정수로 반올림되어 변환된다고 설명한다. 예: 35.7 → 36, 35.5 → 36, -1.5 → -2.

4. 문자열

두 개의 이중 인용부호(" ") 사이에 있는 문자들의 연속을 문자열(string, 스트링)이라고 한다. 문자열은 한 줄 안에 존재해야 하며, 여러 줄에 직접 걸친 문자열은 허용되지 않는다.

문자열을 각 문자당 8비트 ASCII 값의 연속으로 취급하며, 문자열을 저장하는 reg 변수의 폭은 필요한 문자 수 × 8비트로 계산한다.

예시 1-8: 12문자 문자열 저장
reg [8*12:1] string_var;

initial begin
    string_var = "Hello world!";
end
문자 1개→8비트 ASCII →12문자→96비트

4.1 문자열 폭이 변수 폭과 다를 때

  • 변수의 비트 폭이 문자열보다 크면 변수의 왼쪽에 0이 채워진다.
  • 변수의 비트 폭이 문자열보다 작으면 문자열의 오른쪽부터 저장되고, 왼쪽 부분은 잘려 나간다.
예시 1-9: 문자열 출력
module string_test;
    reg [8*14:1] string_var;

    initial begin
        string_var = "Hello world";
        $display("%s is stored as %h", string_var, string_var);

        string_var = {string_var, "!!!"};
        $display("%s is stored as %h", string_var, string_var);
    end
endmodule
Hello world is stored as 00000048656c6c6f20776f726c64
Hello world!!! is stored as 48656c6c6f20776f726c64212121

5. 식별자와 키워드

5.1 식별자(identifier)

식별자는 객체에 이름을 붙이기 위해 사용한다. 단순 식별자와 확장 식별자로 구분한다.

  • 알파벳, 숫자, $, 밑줄(_) 등을 사용할 수 있다.
  • 첫 문자는 알파벳 또는 밑줄이어야 한다.
  • 첫 문자로 숫자나 $는 사용할 수 없다.
  • 대문자와 소문자를 서로 다른 문자로 취급한다.
예시 1-10: 유효한 식별자

6. 시스템 태스크와 시스템 함수

문자 $는 시스템 태스크(system task, 시스템 태스크)와 시스템 함수(system function, 시스템 함수)를 호출할 때 사용된다. $ 뒤의 식별자는 시스템 태스크 또는 시스템 함수로 해석된다.

예시 1-11
$display("display a message");  // 문자열 출력
$finish;                        // 시뮬레이션 종료
구분해서 이해
이 절의 예는 회로 자체의 데이터패스가 아니라 시뮬레이션 동작을 제어하거나 확인하는 코드의 대표적인 형태다.

7. 컴파일러 지시어

grave accent 또는 backtick(`)은 컴파일러 지시어(compiler directive, 컴파일러 디렉티브)를 지정할 때 사용된다. 지시어는 Verilog 소스의 컴파일 과정에 영향을 주며, 읽힌 시점부터 효력이 발생한다.

예시 1-12
`define wordsize 8

이 예에서 소스 코드 안의 wordsize 매크로는 8로 치환되어 컴파일된다.

8. 속성(attribute)

속성은 Verilog HDL을 지원하는 시뮬레이터나 회로 합성 툴의 동작을 제어하기 위해 객체, 문장, 문장 그룹에 부가할 수 있다. 기본 형식은 다음과 같다.

(* attribute_name = value *)
주의
속성의 구체적인 의미와 지원 여부는 사용하는 EDA(Electronic Design Automation, 전자설계자동화) 툴의 설명서를 확인하도록 안내한다.

8.1 case 문에 속성 부가

예시 1-13
(* full_case, parallel_case *)
case (foo)
    <case_statements>

(* full_case = 1, parallel_case = 1 *)
case (foo)
    <case_statements>

8.2 일부 속성만 지정

예시 1-14
(* full_case *)  // parallel_case not specified
case (foo)
    <case_statements>

(* full_case = 1, parallel_case = 0 *)
case (foo)
    <case_statements>

8.3 여러 위치에 속성 지정

예시 1-15
(* optimize_power = 1 *)
module mod1 (
    input  a,
    input  b,
    input  c,
    input  d,
    output y
);

wire sum;

assign sum = b + c;
assign y   = a ? sum : d;

// 속성은 연산자나 조건 연산자 위치에도 지정할 수 있다.
// 예:
// assign sum = b + (* mode = "cla" *) c;
// assign y   = a ? (* no_glitch *) c : d;

endmodule


module top_attr (
    input  a,
    input  b,
    input  c,
    input  d,
    output y
);

(* optimize_power = 0 *)
mod1 synth1 (
    .a(a),
    .b(b),
    .c(c),
    .d(d),
    .y(y)
);

endmodule
지정 위치예시
모듈 정의(* optimize_power=1 *) module ...
모듈 인스턴스(* optimize_power=0 *) mod1 synth1(...)
연산자b + (* mode="cla" *) c
함수 호출add (* mode="cla" *) (b,c)
조건 연산자? (* no_glitch *)

10. Verilog HDL 모델링 방법 전체 개요

Verilog HDL(베릴로그 HDL, 하드웨어 기술 언어)의 구문은 크게 회로 합성용, 시뮬레이션용, 라이브러리 설계용의 세 유형으로 구분한다.

① 회로 합성 지원

assign, always, if~else, case, for, repeat, bufif0, generate, function 등

② 시뮬레이션 지원

initial, forever, $finish, $display 등

③ 라이브러리 설계

specify, table, $width 등

핵심 구분
RTL(Register Transfer Level, 레지스터 전송 수준) 회로 모델링에서는 합성이 지원되는 구문을 사용해야 하며, 테스트벤치 작성에는 시뮬레이션 전용 구문이 사용된다. 라이브러리 설계용 구문은 셀의 기능·지연·핀 정보 등을 정의하는 데 사용된다.

1.1 세 종류의 구문을 한눈에 보기

분류주요 목적대표 예
회로 합성용 실제 논리회로 구조와 동작을 기술 assign, always, if, case
시뮬레이션용 입력 생성, 결과 표시, 시뮬레이션 종료 등 검증 환경 구성 initial, #delay, $display, $finish
라이브러리 설계용 셀 라이브러리의 기능·타이밍·핀 특성 기술 specify, table

11. Verilog HDL 모듈

Verilog HDL은 module(모듈)을 기본 설계 단위로 한다. 모듈은 module로 시작하여 endmodule로 끝나며, 모듈을 머리부 → 선언부 → 몸체부의 세 부분으로 구분한다.

module module_name (port_list);
머리부
module 이름 · 포트 목록
선언부
port 선언 · reg 선언 · wire 선언 · parameter 선언
몸체부
하위모듈 인스턴스 · 게이트 프리미티브 · always/initial 블록 · assign 문 · function/task 정의와 호출
endmodule

2.1 머리부

  • module 키워드로 시작한다.
  • 모듈 이름과 포트 목록을 작성하고 세미콜론(;)으로 끝낸다.
  • 모듈 이름식별자 규칙을 따르며 Verilog 키워드와 같은 이름은 사용할 수 없다.
  • 가독성을 위해 밑줄(_)을 사용할 수 있다.
  • 모듈 기능을 함축적으로 나타내는 이름을 사용하는 것이 바람직하다.
  • 테스트벤치 모듈은 외부 포트가 없으므로 포트 목록을 생략할 수 있다.

2.2 선언부

입력·출력 포트, 자료형, parameter 등 모듈 내부에서 필요한 객체를 선언한다. 포트 목록에서 포트 방향과 자료형까지 선언한 경우에는 선언부에서 동일 포트를 다시 선언하지 않는다.

2.3 몸체부

모듈의 실제 기능과 구조가 표현되는 영역이다. 게이트 프리미티브, 하위모듈 인스턴스, always, initial, assign, 함수와 태스크 등을 조합해 모델링한다.

Verilog를 C 언어처럼 위에서 아래로 읽으면 안 되는 이유
모듈 몸체에 있는 여러 문장은 기본적으로 병행(concurrent) 동작한다. 따라서 서로 독립적인 assign 문이나 게이트 인스턴스는 소스에 적힌 순서대로 한 줄씩 실행되는 것이 아니다. 반면 always, initial, function, task 내부의 문장은 블록 내부의 절차적 순서가 결과에 영향을 줄 수 있다.

12. 회로 모델링 방법

동일한 디지털 회로를 표현하는 방법으로 게이트 프리미티브 모델링, 연속 할당 모델링, 행위수준 모델링, 하위모듈 인스턴스를 이용한 구조적 모델링을 소개한다.

방법무엇을 직접 표현하는가대표 구문
게이트 프리미티브 AND, OR, XOR, NOT 등의 논리 게이트 연결 and, or, xor, not
연속 할당 논리식과 신호의 조합 관계 assign
행위수준 입력 조건에 따른 회로의 동작 always, if, case
구조적 모델링 여러 하위모듈을 연결한 계층 구조 module instance

13. 게이트 프리미티브를 이용한 모델링

의 반가산기(half adder, 하프 애더)는 입력 a, b와 출력 sum, cout으로 구성된다. XOR 게이트와 NAND → NOT 경로를 사용해 반가산기를 구성한다.

a, b →
XOR
→ sum
a, b →
NAND
→
NOT
→ cout
그림 1-9(b)의 모델링 코드
module half_adder (
    input  a,
    input  b,
    output sum,
    output cout
);

wire cout_bar;

xor U0(sum, a, b);
nand   (cout_bar, a, b);
not    (cout, cout_bar);

endmodule

4.1 실제 회로 구조

  • xor U0(sum, a, b); → 입력 a, b를 받는 XOR 게이트
  • nand(cout_bar, a, b); → NAND 게이트 출력이 내부선 cout_bar로 전달
  • not(cout, cout_bar); → cout_bar를 반전하여 cout 생성
병행 동작
세 게이트 인스턴스는 위에서 아래로 실행되는 명령이 아니다. 하드웨어에서 세 회로가 동시에 존재하며 입력이 바뀌면 각 게이트의 출력이 함께 반응한다.

14. 연속 할당문을 이용한 모델링

같은 반가산기를 게이트 인스턴스 대신 논리식으로 직접 표현할 수도 있다. 연속 할당은 assign 문을 사용한다.

코드 1-1: 연속 할당문을 이용한 반가산기
module half_adder2 (
    input  a,
    input  b,
    output sum,
    output cout
);

assign cout = a & b;
assign sum  = a ^ b;

endmodule
Carry
cout = a & b
두 입력이 모두 1일 때 1
Sum
sum = a ^ b
두 입력이 서로 다를 때 1
CODE → 회로
assign cout = a & b;는 AND 조합논리, assign sum = a ^ b;는 XOR 조합논리에 대응한다. 두 문장은 클록 없이 입력 변화에 따라 연속적으로 출력이 결정된다.

15. 행위수준 모델링

행위수준 모델링은 조합회로와 순차회로를 모두 기술할 수 있으며, 테스트벤치 작성에도 사용된다. 2비트 2:1 멀티플렉서와 D 플립플롭을 예제로 제시한다.

6.1 2비트 2:1 멀티플렉서

in0[1:0] ↘
2:1 MUX
sel
→ out[1:0] ↗ in1[1:0]
그림 1-10(b)
module mux2b_if (
    input  [1:0] in0,
    input  [1:0] in1,
    input        sel,
    output [1:0] out
);

reg [1:0] out;

always @(sel or in0 or in1) begin
    if (sel == 0)
        out = in0;
    else
        out = in1;
end

endmodule
selout회로 동작
0in0첫 번째 2비트 입력 선택
1in1두 번째 2비트 입력 선택
조합논리라는 점이 중요
sel, in0, in1 중 하나가 변하면 always 블록이 다시 평가되어 out이 결정된다. 여기에는 클록에 의해 저장되는 상태가 없다.

6.2 D 플립플롭

din →
D Flip-Flop
posedge clk
→ q
그림 1-11(b)
module D_ff (
    input  clk,
    input  din,
    input  rst,
    output q
);

reg q;

always @(posedge clk or posedge rst) begin
    if (rst == 1)
        q <= 1'b0;
    else
        q <= din;
end

endmodule

회로 기준으로 해석

rst 상승 → q를 0으로 리셋
clk 상승에지 → 현재 din 값 샘플링 → q 레지스터 저장
조합회로와 순차회로의 차이
멀티플렉서는 입력이 변하면 출력이 결정되지만, D 플립플롭의 q는 클록 상승에지에서 din 값을 저장하는 순차논리다.

16. 하위모듈 인스턴스를 이용한 구조적 모델링

에서는 1비트 전가산기(full adder, 풀 애더)를 2개의 반가산기 + 1개의 OR 게이트로 구성한다.

half_adder U1
w1, w2 →
half_adder U2
→ sum
w2 ↘
OR U3
→ cout ↗ w3
코드 1-2: 모듈 인스턴스를 이용한 전가산기
module full_add (
    input  a,
    input  b,
    input  cin,
    output sum,
    output cout
);

wire w1, w2, w3;

half_adder U1(
    .a(a), .b(b), .sum(w1), .cout(w2)
);

half_adder U2(w1, cin, sum, w3);

or U3(cout, w2, w3);

endmodule

7.1 신호 흐름

a, b → U1 half_adder → w1, w2
w1, cin → U2 half_adder → sum, w3
w2, w3 → OR U3 → cout

7.2 두 가지 포트 연결 방법

연결 방법예특징
이름에 의한 연결 .a(a), .b(b), .sum(w1), .cout(w2) 포트 이름을 직접 지정
순서에 의한 연결 U2(w1, cin, sum, w3) 하위모듈의 포트 선언 순서에 맞춰 연결
구조적 모델링핵심
이미 만들어진 모듈을 하나의 독립된 하드웨어 블록처럼 사용한다. 따라서 큰 회로를 여러 하위 기능 블록으로 나누고 다시 연결하는 계층적 설계가 가능하다.

17. 테스트벤치 모듈

회로 모델링이 완료되면 시뮬레이션을 통해 기능과 동작 타이밍을 검증해야 한다. 설계된 모듈에 시험 입력을 넣고 응답을 관찰하기 위한 Verilog HDL 모듈을 testbench(테스트벤치)라고 한다.

Stimulus
입력 생성 → DUT
시뮬레이션 대상 모듈 → Response
결과 관찰

8.1 테스트벤치의 세 구성 요소

  1. 시뮬레이션 대상 모듈의 인스턴스
  2. 시뮬레이션 입력을 생성하는 initial 또는 always 문
  3. 시뮬레이션 제어와 출력 응답을 관찰하는 구문
테스트벤치는 실제 FPGA 회로가 아니다
테스트벤치를 회로 설계 모듈과 분리하여 별도 파일로 작성하는 것이 일반적이라고 설명한다. #delay, $finish, $monitor, $display, $write 등은 시뮬레이션 검증에서 사용된다.

8.2 기본 테스트벤치 예

    #50 a = 1'b0; c = 1'b1;

    #50 $finish;
end

endmodule

8.3 반가산기 테스트벤치

코드 1-3
module tb_half_adder;

reg a, b;

half_adder U0_half_adder(a, b, sum, cout);

initial begin
    a = 0; b = 0;

    #10 a = 1;
    #10 a = 0; b = 1;
    #10 a = 1;
    #10 a = 0; b = 0;
    #10 $finish;
end

endmodule

Stimulus 흐름

00→ 10 time 10→ 10 time 01→ 10 time 11→ 10 time 00
반가산기 검증 관점
2개의 1비트 입력 a, b가 가질 수 있는 4가지 조합인 00, 01, 10, 11을 모두 입력해 보는 구조다. 즉, 가능한 입력 조건을 빠짐없이 자극하여 결과를 확인한다.

8.4 D 플립플롭 테스트벤치와 클록 생성

의 예는 dff_sr 모듈 검증을 위해 클록 생성용 initial 블록과 set, reset, din을 만드는 또 하나의 initial 블록을 사용한다.

코드 1-4
module tb_dff_sr;

reg set, reset, clock, din;

dff_sr U0_dff_sr(set, reset, clock, din, q, qb);

initial begin
    clock = 1'b0;

    forever begin
        #10 clock = ~clock;
    end
end

initial begin
    forever begin
        din = 0; reset = 1; set = 1;

        #15 din = 1;
        #30 reset = 0;
        #10 reset = 1;
        #25 din = 0;
        #20 set = 0;
        #10 set = 1;
        #30 din = 0;
    end
end

endmodule

클록이 만들어지는 과정

clock = 0 → #10 clock = 1 → #10 clock = 0 → 반복
클록 주기
클록은 10 time unit마다 반전되므로, LOW 10 + HIGH 10의 한 주기는 20 time unit이다. 이를 20 ns 주기의 클록으로 설명한다.
초기화가 필요한 이유
reg의 초기값이 기본적으로 x(unknown)이므로 clock = ~clock; 방식으로 클록을 생성하려면 먼저 clock = 1'b0;처럼 확정된 값으로 초기화해야 한다고 설명한다.
