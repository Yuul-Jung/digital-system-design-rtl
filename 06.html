1. CHAPTER 06 전체 개요

Verilog HDL에서 하드웨어 설계의 기본 단위는 module(모듈)이다. 구조적 모델링(structural modeling)은 큰 회로를 여러 하위 모듈로 나누고, 상위 모듈에서 하위 모듈을 인스턴스(instance)한 뒤 포트를 통해 신호를 연결하여 전체 하드웨어를 구성하는 방법이다.

모듈

재사용 가능한 독립 하드웨어 블록

인스턴스

정의된 모듈을 실제 상위 회로 안에 배치한 복사본

포트 연결

상위 신호와 하위 모듈의 input/output/inout을 연결

parameter / generate

비트 폭·깊이·구현 구조를 파라미터화하여 재사용

System / Top Module
↓
Board / Sub Module A
Board / Sub Module B
↓
IC / Controller
ALU / MUX / Flip-Flop
비유
시스템 → 보드 → IC → 플립플롭·멀티플렉서·ALU처럼 상위 블록을 여러 하위 블록으로 분해하는 방식이 Verilog의 계층적 구조적 설계와 대응된다.
모듈 정의의 내포는 허용되지 않음
하나의 module ... endmodule 내부에 다른 module ... endmodule 정의를 직접 넣는 방식은 허용되지 않는다. 필요한 하위 모듈은 각각 독립적으로 정의한 후 상위 모듈에서 인스턴스한다.
CODE → 하드웨어 구조
모듈 정의는 “부품의 설계도”에 가깝고, 모듈 인스턴스는 상위 회로에 실제로 배치된 “부품 한 개”에 해당한다. 같은 모듈을 여러 번 인스턴스하면 동일한 기능의 하드웨어 블록이 여러 개 만들어진다.

2. 6.1 모듈

Verilog 모듈을 크게 타이틀 부분 → 선언 부분 → 몸체 부분으로 구분한다.

module module_name (port_list);
타이틀 부분
module 이름 · parameter 목록(선택) · port 목록 또는 port declaration 목록
선언 부분
input/output/inout · reg · wire · parameter 등의 선언
몸체 부분
모듈 인스턴스 · gate primitive · generate · assign · always · initial · function · task
endmodule
그림 6-1의 기본 구조
module module_name (port_list);

    // declarations
    // port 선언
    // reg 선언
    // wire 선언
    // parameter 선언

    // module items
    // 모듈 인스턴스
    // gate primitive 인스턴스
    // generate 블록
    // assign 문
    // always 문, initial 문
    // function, task 정의/호출

endmodule
이름 작성의 의미
모듈 이름이 기능을 함축적으로 나타내는 것이 좋다고 설명한다. 예를 들어 adder_8b는 이름만 보고도 “8비트 가산기 모듈”임을 예상할 수 있다.

2.1 두 가지 모듈 정의 형식

방법 ① ANSI-C 형식 
module module_name (
    input  a,
    input  b,
    output y
);

assign y = a & b;

endmodule

포트 목록 안에 방향·자료형·범위를 함께 선언한다.

방법 ② 포트 목록/선언 분리 
module module_name (a, b, y);

input  a;
input  b;
output y;

assign y = a & b;

endmodule

타이틀에는 이름만 나열하고 선언 부분에서 별도로 선언한다.

순서에 의한 포트 연결과 관계
모듈 타이틀에 포트가 나열된 순서는 나중에 하위 모듈을 순서에 의해 포트 연결할 때 직접 사용된다. 따라서 포트 순서는 구조적 설계에서 의미가 있다.

3. 6.1.1 모듈 포트의 선언

input [net_type] [signed] [range] port_name; output [net_type] [reg] [signed] [range] port_name; inout [net_type] [signed] [range] port_name;
포트 방향의미핵심
input외부 → 모듈 내부모듈이 입력값을 받음
output모듈 내부 → 외부모듈 결과를 외부로 전달
inout양방향양쪽 방향으로 신호 전달 가능

3.1 signed 속성

포트나 연결 신호가 signed로 선언되면 해당 비트패턴은 2의 보수 부호값으로 해석된다. 명시적으로 signed가 지정되지 않은 일반 net는 unsigned로 취급된다.

3.2 포트 내부/외부 자료형 규칙

위치inputoutputinout
모듈 인스턴스 외부 net 또는 variable
real 예외		 net net
모듈 정의 내부 net net 또는 variable
real 예외		 net
real 값의 포트 전달
real 값은 직접 포트로 연결하지 않고 $realtobits로 64비트 벡터로 변환해 전달한 뒤, 수신부에서 $bitstoreal로 복원한다.

3.3 포트 선언 예

예시 6-1
module port_example (
    a, b, sel, c, result, sum, data_bus, addr
);

input [15:0] a, b;
input sel;

input signed [7:0] c;

output signed [15:0] result;
output signed reg [7:0] sum;

inout [32:1] data_bus;

parameter WORD = 32;

input [WORD-1:0] addr;

endmodule
선언의미
input [15:0] a,b16비트 입력 2개
input sel1비트 입력
input signed [7:0] c8비트 signed 입력
output signed reg [7:0] sum내부 절차형 할당에 사용할 수 있는 signed reg 출력
inout [32:1] data_bus32비트 양방향 포트
input [WORD-1:0] addrparameter를 이용해 폭을 결정하는 입력

3.4 중복 선언 오류

input  aport;   // 첫 번째 선언
input  aport;   // 오류: 중복 선언
output aport;   // 오류: 중복 선언
같은 포트 이름은 한 범위 안에서 중복 선언할 수 없다.

4. 6.1.2 포트선언목록

Verilog-2001의 ANSI 형식에서는 포트 목록에 방향, 비트 폭, 자료형, signed 속성까지 함께 넣어 한 번에 완전한 포트 선언을 만들 수 있다.

예시 6-3
module port_example (
    input  [15:0] a,
    input  [15:0] b,
    input         sel,
    input  signed [7:0] c,

    output signed [15:0] result,
    output signed reg [7:0] sum,

    inout  [32:1] data_bus,
    input  [WORD-1:0] addr
);

parameter WORD = 32;

endmodule
핵심
포트선언목록에서 이미 완전하게 선언한 포트는 선언부에서 다시 중복 선언하지 않는다.

4.1 다양한 포트 표현

예시 6-4
module complex_ports ({c,d}, .e(f));
    // {c,d}: 첫 번째 포트
    // 외부 포트 이름 e에 내부 이름 f 연결
endmodule

module split_ports (a[7:4], a[3:0]);
    // a의 상위 4비트와 하위 4비트를 각각 포트로 사용
endmodule

module same_port (.a(i), .b(i));
    // 내부 이름 i를 외부 포트 a, b와 연결
endmodule

module renamed_concat (.a({b,c}), f, .g(h[1]));
    // 결합, 이름 변경, 비트 선택을 이용한 포트 표현
endmodule
핵심
포트는 단순한 전체 신호 이름만이 아니라 비트 선택, 부분 선택, 결합, 외부 이름과 내부 이름의 대응처럼 다양한 형식으로 정의될 수 있다. 다만 이러한 정의 방식은 이후 이름에 의한 포트 연결 가능 여부에 영향을 줄 수 있다.

5. 6.2 모듈 인스턴스

구조적 설계는 이미 정의된 하위 모듈을 상위 모듈 내부에 인스턴스하고 포트를 연결하는 방식으로 이루어진다.

module_name [parameter_value] instance_name [range] (port_connections);
요소역할
module_name어떤 설계도를 사용할지 결정
parameter_value필요할 때 하위모듈 parameter 값 변경
instance_name상위 계층 안에서 해당 복사본을 식별
[range]같은 모듈의 인스턴스 배열 생성
port_connections상위 신호와 하위 포트 연결
모듈 인스턴스 이름은 생략할 수 없음
게이트 프리미티브와 달리 모듈 인스턴스에는 반드시 고유한 인스턴스 이름이 필요하다고 설명한다.

5.1 parameter 값 변경 형식

#(value1, value2, ...) #( .parameter_name1(value1), .parameter_name2(value2) )

localparam, specparam은 외부 인스턴스에서 이 방식으로 변경할 수 없고, 모듈 내부의 parameter만 변경 대상이 된다.

6. 6.2.1 포트 연결 형식

순서에 의한 연결 
module_name U0 (
    signal1,
    signal2,
    signal3
);

하위 모듈의 포트 선언 순서와 1:1 대응한다.

이름에 의한 연결 
module_name U0 (
    .port1(signal1),
    .port2(signal2),
    .port3(signal3)
);

포트 이름을 직접 지정하므로 나열 순서가 중요하지 않다.

한 인스턴스 안에서 두 방식을 혼용할 수 없음
특정 모듈 인스턴스는 전체 포트를 순서 방식으로 연결하거나, 전체 포트를 이름 방식으로 연결해야 한다.

6.1 modB 포트 연결 비교

코드 6-1(a): 하위모듈
module modB (
    output wa,
    input  b,
    input  c,
    input  d
);

bufif1 g1 (wa, b, cinvert);
not #(2,6) n1 (cinvert, int);
and #(6,5) g2 (int, c, d);

endmodule
코드 6-1(b): 순서 연결
module top_mod;

wire [2:0] v;
wire w;

modB b1 (
    w,
    v[2],
    v[1],
    v[0]
);

endmodule
modB 포트상위 신호
waw
bv[2]
cv[1]
dv[0]
코드 6-1(c): 이름 연결
module top_mod;

wire [2:0] v;
wire w;

modB b1 (
    .wa(w),
    .d(v[0]),
    .c(v[1]),
    .b(v[2])
);

endmodule
이름 연결의 장점
포트가 선언된 순서와 다르게 적어도 포트 이름으로 연결 관계가 명확하다.

6.2 사용하지 않는 포트

ALPHA U0 (
    .out(topB),
    .in1(topA),
    .in2()
);

연결하지 않는 포트를 .port_name()처럼 빈 괄호로 표현할 수 있다고 설명한다.

6.3 동일 포트 중복 연결 오류

modX U0 (
    .i(a),
    .i(b),   // 오류
    .o(c),
    .o(d),   // 오류
    .e(f)
);

7. 포트 연결과 구조적 설계 예

7.1 parameter를 갖는 D 플립플롭과 5비트 레지스터

코드 6-3(a): dff
module dff (
    output q,
    input  clk,
    input  d
);

parameter delay = 1;

reg q;

always @(posedge clk) begin
    #delay q <= d;
end

endmodule
코드 6-3(b): reg_5b
module reg_5b (
    output [4:0] qout,
    input        clk,
    input  [4:0] din
);

dff u1 (
    qout[0], clk, din[0]
);

dff u2 (
    .clk(clk),
    .q(qout[1]),
    .d(din[1])
);

dff u3 (
    qout[2], clk, din[2]
);

defparam u3.delay = 2.5;

dff #(3) u4 (
    qout[3], clk, din[3]
);

dff #(
    .delay(4)
) u5 (
    qout[4], clk, din[4]
);

endmodule
인스턴스포트 연결parameter 변경
u1순서기본값
u2이름기본값
u3순서defparam으로 2.5
u4순서#(3)
u5순서#(.delay(4))
Simulation 지연과 실제 FPGA 지연
#delay는 시뮬레이션 시간 제어이며, 실제 FPGA의 물리적 지연은 구현 후 Timing Report에서 확인한다.

7.2 1비트 전가산기 — 두 개의 반가산기 + OR

코드 6-4(a): half_adder
module half_adder (
    input  a,
    input  b,
    output sum,
    output cout
);

xor U0 (sum, a, b);
nand    (cout_bar, a, b);
not U1 (cout, cout_bar);

endmodule
코드 6-4(b): full_adder
module full_adder (
    input  a,
    input  b,
    input  cin,
    output sum,
    output cout
);

half_adder u0 (
    a,
    b,
    temp_sum,
    temp_c1
);

half_adder u1 (
    .a(temp_sum),
    .b(cin),
    .sum(sum),
    .cout(temp_c2)
);

or u2 (
    cout,
    temp_c1,
    temp_c2
);

endmodule
a,b → half_adder u0 → temp_sum, temp_c1
temp_sum, cin → half_adder u1 → sum, temp_c2
temp_c1, temp_c2 → OR u2 → cout
구조적 모델링핵심
full_adder는 반가산기의 내부 논리식을 다시 작성하지 않는다. 이미 정의된 half_adder를 하드웨어 블록으로 재사용하고, 중간 신호를 wire처럼 연결하여 더 큰 회로를 만든다.

7.3 전가산기 테스트벤치

코드 6-5
module tb_full_adder;

reg a, b, cin;
integer k;

full_adder U0 (
    a, b, cin,
    sum, cout
);

initial begin
    for (k = 0; k < 8; k = k + 1) begin
        cin = k / 4;
        b   = (k % 4) / 2;
        a   = k % 2;

        #10;
    end

    #10 $finish;
end

endmodule

k=0~7을 이용해 {cin,b,a}의 8개 가능한 입력 조합을 순차적으로 만든다.

8. 인스턴스 배열

동일한 모듈을 여러 번 반복 배치할 때 인스턴스 이름 뒤에 범위를 지정하여 인스턴스 배열을 만들 수 있다.

8.1 개별 인스턴스 방식

코드 6-6(a)
module bus_driver (
    input  [15:0] busin,
    input         enh,
    input         enl,
    output [7:0]  bushigh,
    output [7:0]  buslow
);

driver busar3 (
    busin[15:12], bushigh[7:4], enh
);

driver busar2 (
    busin[11:8], bushigh[3:0], enh
);

driver busar1 (
    busin[7:4], buslow[7:4], enl
);

driver busar0 (
    busin[3:0], buslow[3:0], enl
);

endmodule

8.2 인스턴스 배열 방식

코드 6-6(b)
module bus_driver (
    input  [15:0] busin,
    input         enh,
    input         enl,
    output [7:0]  bushigh,
    output [7:0]  buslow
);

driver busar [3:0] (
    .in(busin),
    .out({bushigh, buslow}),
    .en({enh, enh, enl, enl})
);

endmodule
무엇이 줄어든 것인가?
네 개의 같은 driver 인스턴스를 한 줄의 인스턴스 배열로 표현한다. 포트에 연결되는 벡터와 결합 연산자는 배열의 각 인스턴스에 대응하여 분배된다.

9. 6.2.2 실수형 값의 포트 연결

real 값을 모듈 포트에 직접 연결하지 않고 64비트 비트 벡터로 변환한 뒤 전달하는 방법을 설명한다.

코드 6-7: real → bits
module driver (
    output net_r
);

real r;

wire [64:1] net_r = $realtobits(r);

endmodule
코드 6-8: bits → real
module receiver (
    input net_r
);

wire [64:1] net_r;
real r;

initial
    r = $bitstoreal(net_r);

endmodule
real r → $realtobits 64비트 벡터 → 포트 전달 64비트 벡터 → $bitstoreal real r

10. 6.3 모듈 parameter

parameter는 하나의 RTL 모듈을 여러 비트 폭, 깊이, 지연값 또는 구현 조건으로 재사용하기 위한 중요한 수단이다. 모듈 외부의 인스턴스에서 값을 변경할 수 있다. 반면 localparam은 모듈 내부 상수로 사용되며 외부에서 직접 변경하지 않는다.

구분parameterlocalparam
상수예예
모듈 인스턴스에서 변경가능불가
주요 용도모듈 맞춤화내부 파생 상수

10.1 자료형/범위에 따른 parameter 값 해석

  • 자료형과 범위가 모두 없으면 최종 할당값이 자신의 기본 자료형·범위를 결정한다.
  • 범위만 지정되면 해당 범위의 unsigned parameter가 된다.
  • 자료형만 지정되면 지정 자료형으로 변환된다.
  • signed와 범위를 함께 지정하면 해당 signed/폭을 유지한다.
코드 6-9(a)
module mod_param (a, b);

real r1, r2;

parameter [2:0] A = 3'h2;
parameter       B = 2;

initial begin
    r1 = A;
    r2 = B;

    $display(
        "r1 is %f, r2 is %f",
        r1, r2
    );
end

endmodule
코드 6-9(b)
module mod_defparam;

wire a, b;

defparam U0.A = 3.1415;
defparam U0.B = 3.1415;

mod_param U0 (a, b);

endmodule
해석
A는 [2:0] 범위를 가지고 있으므로 3.1415가 정수화/폭 변환되어 A의 3비트 형식에 맞춰진다. B는 자료형과 범위가 명시되지 않았으므로 변경된 값의 성격을 따른다.

11. 6.3.1 defparam 문

defparam은 인스턴스의 계층적 이름을 사용해 하위모듈 parameter 값을 바꾸는 방법이다.

코드 6-10(a): vdff
module vdff (
    input                 clk,
    input  [size-1:0]     in,
    output reg [size-1:0] out
);

parameter size  = 1;
parameter delay = 1;

always @(posedge clk)
    #delay out <= in;

endmodule
코드 6-10(b): top
module top (
    input        clk,
    input  [4:0] in1,
    input  [9:0] in2,
    output [4:0] out1,
    output [9:0] out2
);

defparam
    top.m1.size  = 5,
    top.m1.delay = 10,
    top.m2.size  = 10,
    top.m2.delay = 20;

vdff m1 (
    clk, in1, out1
);

vdff m2 (
    clk, in2, out2
);

endmodule
vdff 기본 size=1 → m1.size=5 → 5비트 레지스터
vdff 기본 size=1 → m2.size=10 → 10비트 레지스터
합성 구조
6-4는 parameter 변경에 따라 같은 vdff 정의에서 5비트와 10비트 크기의 서로 다른 하드웨어 인스턴스가 생성되는 모습을 보여준다.

12. 6.3.2 모듈 인스턴스에서 parameter 값 변경

12.1 순서에 의한 변경

module_name #(value1, value2, ...) instance_name (port_connections);

하위모듈에서 parameter가 선언된 순서와 #(...) 안 값의 순서가 1:1 대응한다.

12.2 이름에 의한 변경

module_name #( .param_name1(value1), .param_name2(value2) ) instance_name (port_connections);

선언 순서와 무관하게 parameter 이름으로 원하는 항목만 변경할 수 있다.

12.3 파라미터 + 인스턴스 배열을 이용한 M×N 레지스터

코드 6-11(a): DFF
module DFF (
    input      clk,
    input      in,
    output reg out
);

always @(posedge clk)
    out <= in;

endmodule
코드 6-11(b): dffn
module dffn (
    input                   clk,
    input  [BITS-1:0]       d,
    output [BITS-1:0]       q
);

parameter BITS = 1;

DFF dff_array [BITS-1:0] (
    .clk(clk),
    .in(d),
    .out(q)
);

endmodule
코드 6-11(c): MxN_register
module MxN_register (
    input          clk,
    input  [M-1:0] in,
    output [M-1:0] out
);

parameter M = 3;
parameter N = 4;

wire [M*(N-1):1] t;

// dffn의 BITS를 M으로 변경
dffn #(M) p [1:N] (
    .clk(clk),
    .d({t, in}),
    .q({out, t})
);

endmodule
합성 구조 해석
6-5는 M=3, N=4 조건에서 3비트 폭의 레지스터 단계가 깊이 4로 연결된 구조, 즉 DFF의 2차원 배열 형태로 확장된 회로를 보여준다.

13. 6.3.3 모듈 parameter의 상호 의존성

한 parameter가 다른 parameter를 이용해 계산되면 원본 parameter 값이 변경될 때 파생 parameter도 함께 바뀐다.

예시 6-6
parameter
    word_size   = 32,
    memory_size = word_size * 4096;
word_size 변경 → memory_size 식 재계산 → 파라미터화된 메모리 크기 변화
설계 의미
관련된 폭과 용량을 각각 따로 수동 수정하지 않고, 하나의 기준 parameter를 변경하면 종속 parameter가 자동으로 따라가도록 만들 수 있다.

14. 6.4 생성문(generate)

생성문은 elaboration(엘라보레이션, 시뮬레이션/합성 전에 설계 계층과 parameter를 확정하는 단계)에서 조건에 따라 하드웨어 인스턴스를 여러 개 만들거나 특정 구현을 선택하기 위한 구문이다.

generate // generate items endgenerate

14.1 생성 가능한 항목

net 선언
variable 선언
assign
module instance
gate primitive
always / initial
function / task
제한
generate 내부에서 parameter, localparam, input, output, inout 선언은 허용되지 않는다고 설명한다. 또한 반복 generate 내부에서는 function/task 선언에 제한이 있다.

14.2 생성문의 주요 형태

  • generate block
  • generate-if
  • generate-case
  • generate-for

15. 6.4.1 genvar 선언

genvar i;

genvar는 generate-for 반복 생성문에서 사용하는 elaboration 전용 정수 인덱스이다.

항목genvar절차형 for의 integer
존재 시점elaboration 동안시뮬레이션/절차 실행 동안
용도하드웨어 인스턴스 생성절차형 문장 반복
시뮬레이션 중 변수로 존재아니오예
genvar가 x, z, 음수 값을 가질 수 없고, 반복 generate에 의해 값이 결정된다고 설명한다.

16. 6.4.2 반복 생성문 — Gray → Binary 변환기

코드 6-13과 6-14는 비트 수를 SIZE parameter로 설정한 파라미터화 Gray code(그레이 코드) → binary(이진) 변환기 예이다.

16.1 assign을 이용한 generate-for

코드 6-13
module gray2bin1 (
    output [SIZE-1:0] bin,
    input  [SIZE-1:0] gray
);

parameter SIZE = 4;

genvar i;

generate
    for (i = 0; i < SIZE; i = i + 1) begin : bit
        assign bin[i] = ^gray[SIZE-1:i];
    end
endgenerate

endmodule
bin[i] ← gray[SIZE-1:i] 전체 XOR 축약

16.2 always를 이용한 generate-for

코드 6-14
module gray2bin2 (
    output [SIZE-1:0] bin,
    input  [SIZE-1:0] gray
);

parameter SIZE = 4;

reg [SIZE-1:0] bin;
genvar i;

generate
    for (i = 0; i < SIZE; i = i + 1) begin : bit
        always @(gray[SIZE-1:i])
            bin[i] = ^gray[SIZE-1:i];
    end
endgenerate

endmodule
generate-for의 의미
이 for는 시뮬레이션 중 매번 반복 실행되는 소프트웨어 루프가 아니다. elaboration 시점에 SIZE만큼의 하드웨어 조각을 복제하여 생성하는 구조이다.

17. 파라미터화된 리플 캐리 가산기

generate-for를 이용해 각 비트의 full-adder 논리를 반복 생성하여 멀티비트 ripple-carry adder(리플 캐리 가산기)를 만든다.

17.1 생성루프 밖에 2차원 net 선언

코드 6-15
module adder_gen1 (
    output              co,
    output [SIZE-1:0]   sum,
    input  [SIZE-1:0]   a,
    input  [SIZE-1:0]   b,
    input               ci
);

parameter SIZE = 4;

wire [SIZE:0] c;
wire [SIZE-1:0] t [1:3];

genvar i;

assign c[0] = ci;

generate
    for (i = 0; i < SIZE; i = i + 1) begin : bit
        xor g1 (t[1][i], a[i], b[i]);
        xor g2 (sum[i],  t[1][i], c[i]);

        and g3 (t[2][i], a[i], b[i]);
        and g4 (t[3][i], t[1][i], c[i]);

        or  g5 (c[i+1],  t[2][i], t[3][i]);
    end
endgenerate

assign co = c[SIZE];

endmodule

비트 i의 데이터패스

a[i], b[i] → XOR t1 + c[i] sum[i]
a[i],b[i] → AND t2
t1,c[i] → AND t3
t2,t3 → OR c[i+1]

17.2 생성루프 안에 지역 wire 선언

코드 6-16
module adder_gen2 (
    output              co,
    output [SIZE-1:0]   sum,
    input  [SIZE-1:0]   a,
    input  [SIZE-1:0]   b,
    input               ci
);

parameter SIZE = 4;

wire [SIZE:0] c;
genvar i;

assign c[0] = ci;

generate
    for (i = 0; i < SIZE; i = i + 1) begin : bit
        wire t1, t2, t3;

        xor g1 (t1,       a[i], b[i]);
        xor g2 (sum[i],   t1,   c[i]);

        and g3 (t2,       a[i], b[i]);
        and g4 (t3,       t1,   c[i]);

        or  g5 (c[i+1],   t2,   t3);
    end
endgenerate

assign co = c[SIZE];

endmodule
두 코드의 차이
코드 6-15는 중간 net을 generate 밖의 2차원 배열로 선언하고, 코드 6-16은 각 반복 블록 내부에 t1,t2,t3를 지역 net으로 생성한다. 6-7은 두 코드가 동일한 4비트 리플 캐리 가산기 구조로 합성됨을 보여준다.

17.3 생성된 인스턴스 이름

begin : bit처럼 generate block 이름을 붙이면 각 반복은 bit[0], bit[1]처럼 고유한 계층 이름을 갖는다.

bit[0].g1 bit[1].g1 bit[2].g1 bit[3].g1

18. 다중 생성루프와 생성 계층 이름

코드 6-17
parameter SIZE = 2;

genvar i, j, k, m;

generate
    for (i = 0; i < SIZE; i = i + 1) begin : B1
        M1 N1();

        for (j = 0; j < SIZE; j = j + 1) begin : B2
            M2 N2();

            for (k = 0; k < SIZE; k = k + 1) begin : B3
                M3 N3();
            end
        end

        if (i > 0) begin : B4
            for (m = 0; m < SIZE; m = m + 1) begin : B5
                M4 N4();
            end
        end
    end
endgenerate

18.1 계층 경로 예

B1[0].N1 B1[1].N1 B1[0].B2[0].N2 B1[0].B2[1].N2 B1[0].B2[0].B3[0].N3 B1[1].B4.B5[0].N4
계층 이름의 형태
generated_block_identifier[genvar_value]가 반복 생성 인스턴스의 범위를 만들고, 그 아래에 실제 모듈 인스턴스 이름이 이어진다.

19. 6.4.3 조건 생성문과 6.4.4 case 생성문

19.1 generate-if

조건 생성문은 elaboration 시점의 상수 조건에 따라 어떤 하드웨어 블록을 실제 설계에 포함할지 결정한다.

코드 6-18
module multiplier (
    input  [a_width-1:0]       a,
    input  [b_width-1:0]       b,
    output [product_width-1:0] product
);

parameter a_width = 8;
parameter b_width = 8;

localparam product_width = a_width + b_width;

generate
    if ((a_width < 8) || (b_width < 8)) begin : MULT
        CLA_mul #(
            a_width,
            b_width
        ) U1 (
            a, b, product
        );
    end
    else begin : MULT
        WALLACE_mul #(
            a_width,
            b_width
        ) U1 (
            a, b, product
        );
    end
endgenerate

endmodule
a_width 또는 b_width < 8 → CLA_mul 인스턴스
그 외 → WALLACE_mul 인스턴스
중요
런타임에 두 곱셈기 사이를 MUX로 선택하는 회로가 아니다. elaboration 시 parameter 조건에 따라 둘 중 하나의 구현만 실제 계층에 생성되는 구조이다.

19.2 generate-case

코드 6-19
generate
    case (WIDTH)
        1: begin : ADDER
            adder_1bit U1 (
                co, sum, a, b, ci
            );
        end

        2: begin : ADDER
            adder_2bit U1 (
                co, sum, a, b, ci
            );
        end

        default: begin : ADDER
            adder_cla #(
                WIDTH
            ) U1 (
                co, sum, a, b, ci
            );
        end
    endcase
endgenerate
WIDTH생성되는 하드웨어
1adder_1bit
2adder_2bit
그 외adder_cla #(WIDTH)

선택된 경로의 계층 인스턴스 이름을 ADDER.U1로 설명한다.

20. 6.5 계층적 이름

Verilog의 모듈, 인스턴스, task, function, named block, generate block 등은 계층구조 안에서 고유한 경로 이름을 가질 수 있다. 각 계층은 점(.)으로 연결된다.

root.instance.sub_instance.block.object

20.1 코드 6-20의 계층 구조

코드 6-20
module wave;

reg stim1, stim2;

cct a (
    stim1,
    stim2
);

initial begin : wave1
    #100 fork : innerwave
        reg hold;
    join

    #150 begin
        stim1 = 0;
    end
end

endmodule


module cct (
    input stim1,
    input stim2
);

mod Amod (stim1),
    Bmod (stim2);

endmodule


module mod (
    input in
);

always @(posedge in) begin : keep
    reg hold;

    hold = in;
end

endmodule
wave
↓
a : cct
wave1 : named initial block
↓
Amod / Bmod
innerwave
↓
keep
hold

20.2 계층 경로 이름 예

wave.stim1 wave.a wave.a.Amod wave.a.Amod.keep wave.a.Amod.keep.hold wave.wave1 wave.wave1.innerwave wave.wave1.innerwave.hold
왜 중요한가?
계층 이름은 대규모 설계에서 “어느 모듈의 어느 인스턴스 안에 있는 어떤 객체인가”를 정확히 식별하는 주소와 같다. parameter 재정의, 시뮬레이션 신호 관찰, 생성 인스턴스 참조 등에 사용된다.

20.3 형제 블록 객체 상호 참조

코드 6-21
begin
    fork : mod_1
        reg x;
        mod_2.x = 1;
    join

    fork : mod_2
        reg x;
        mod_1.x = 0;
    join
end

21. 6.5.1 상향 이름 참조

하위계층 모듈에서도 상위계층의 모듈/인스턴스 이름을 알고 있다면 계층적 경로를 통해 상위 객체를 참조할 수 있다.

module_name.item_name module_instance_name.item_name generate_module_name.item_name

인스턴스 이름을 현재 범위에서 먼저 찾고, 없으면 상위 계층으로 올라가며 같은 이름을 찾는 방식으로 설명한다.

21.1 여러 복사본이 있는 계층에서 이름 참조

코드 6-22
module a;
    integer i;

    b a_b1();
endmodule


module b;
    integer i;

    c b_c1(),
      b_c2();

    initial
        #10 b_c1.i = 2;
endmodule


module c;
    integer i;

    initial begin
        i = 1;

        b.i = 1;
    end
endmodule


module d;
    integer i;

    b d_b1();

    initial begin
        a.i = 1;
        d.i = 5;

        a.a_b1.i = 2;
        a.a_b1.b_c1.i = 3;
        a.a_b1.b_c2.i = 4;

        d.d_b1.i = 6;
        d.d_b1.b_c1.i = 7;
        d.d_b1.b_c2.i = 8;
    end
endmodule

21.2 계층 구조 해석

root: a
root: d
↓ 각각 b 인스턴스
a.a_b1
d.d_b1
↓ 각각 c 두 개
b_c1
b_c2
b_c1
b_c2

따라서 c.i는 설계 전체에서 네 개의 복사본이 존재하며, 전체 경로를 이용하면 각 복사본을 개별적으로 식별할 수 있다.

a.a_b1.b_c1.i a.a_b1.b_c2.i d.d_b1.b_c1.i d.d_b1.b_c2.i

module독립적인 하드웨어 설계 단위재사용 가능한 기능 블록
instance상위 모듈 안에 배치된 모듈 복사본실제 하위 하드웨어 블록 생성
ordered port선언 순서대로 포트 연결순서 오류 주의
named port포트 이름으로 연결연결 의도가 명확
instance array동일 모듈 여러 개 반복 생성버스·레지스터 배열 구조
parameter외부에서 값 변경 가능폭·깊이·구현을 재사용 가능하게 만듦
localparam외부에서 직접 변경 불가내부 파생 상수
defparam계층 이름으로 parameter 변경특정 인스턴스 맞춤화
generate-forelaboration 시 반복 생성동일 하드웨어 블록 여러 개 전개
generate-if/case상수 조건에 따라 구현 선택하드웨어 구조 자체를 선택
genvargenerate 전용 인덱스시뮬레이션 중 존재하지 않음
hierarchical name점으로 이어진 객체 경로대규모 계층 설계의 정확한 객체 식별

③ 각 포트에는 상위의 어떤 신호가 연결되는가?
④ parameter가 바뀌면 비트 폭·깊이·생성 개수가 어떻게 달라지는가?
⑤ generate가 시뮬레이션 중 반복되는 것인가, elaboration에서 하드웨어를 생성하는 것인가?
⑥ 특정 신호나 인스턴스의 전체 계층 경로는 무엇인가?
Digital Design → Verilog RTL → Synthesis 연결
하위 기능 블록을 모듈로 정의하고 상위 모듈에서 인스턴스와 wire를 이용해 연결하면 실제 합성 결과도 같은 계층적 하드웨어 블록 구조로 전개된다. parameter와 generate는 한 개의 RTL 소스로 다른 비트 폭·깊이·구현 구조를 만드는 수단이다. 다만 실제 합성 결과의 세부 최적화, 자원 사용량, 타이밍은 합성/구현 보고서가 없으면 임의로 단정하지 않는다.
