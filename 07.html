1. CHAPTER 07 전체 개요

회로 설계 모듈이나 시뮬레이션 테스트벤치에서 같은 행위수준 코드가 반복되면 전체 소스가 길어지고 가독성이 떨어진다. Verilog HDL은 반복되는 동작을 function(함수) 또는 task(태스크)로 정의한 뒤 필요한 곳에서 호출할 수 있도록 지원한다.

함수 function

하나의 결과 값을 반환하는 zero-delay 계산에 적합하다.

태스크 task

여러 입출력 인수와 시간 제어를 포함하는 더 일반적인 절차를 표현할 수 있다.

공통 목적

반복 코드 제거 · 기능 분할 · 재사용 · 가독성 · 디버깅 용이성

범위
이 장은 사용자가 직접 정의하는 함수와 태스크를 다룬다. Verilog HDL이 기본 제공하는 시스템 함수와 시스템 태스크는 9장에서 다루는 것으로 안내한다.
RTL 관점
함수나 태스크가 별도의 물리적 “함수 호출 회로”를 만든다고 이해하면 안 된다. 합성 가능한 함수/태스크가 RTL에서 사용되면, 그 내부의 연산과 조건이 호출 위치의 하드웨어 논리로 전개되어 구현되는 관점으로 이해하는 것이 좋다.

2. 7.1 함수와 태스크의 차이점

표 7-1은 함수와 태스크를 시간 제어, 인수 방향, 반환 방식, 호출 관계를 중심으로 구분한다.

구분함수 function태스크 task
대표 용도 zero-delay 조합 계산, 하나의 결과 생성 지연·이벤트·타이밍 제어, 여러 결과 또는 결과 없음
시뮬레이션 지연 zero delay non-zero delay 가능
#, @, wait 사용 불가 사용 가능
결과 반환 함수 이름을 통해 하나의 결과 반환 output, inout으로 여러 결과 반환 가능
입력 인수 적어도 하나 이상의 input 필요 0개 이상 가능
output / inout 인수 가질 수 없음 가질 수 있음
다른 함수 호출 가능 가능
다른 태스크 호출 불가 가능
nonblocking 할당 사용 불가 절차형 문장으로 사용 가능

2.1 함수와 태스크의 공통 제한

  • reg, integer, real, time, event 등 variable 자료형 사용 가능
  • wire, tri 등의 net 자료형을 내부 자료형으로 사용할 수 없음
  • if-else, case, for, wait 등 절차형 문장 사용 가능
  • always 블록이나 initial 블록 자체를 함수/태스크 내부에 포함할 수 없음
  • 게이트 프리미티브 또는 모듈 인스턴스를 내부에 둘 수 없음
  • always, initial, 다른 함수/태스크에서 호출될 수 있음
가장 쉬운 구분
“즉시 하나의 계산값이 필요하다” → 함수
“여러 값을 주고받거나 시간 흐름까지 포함해야 한다” → 태스크

3. 같은 기능을 함수와 태스크로 호출하는 방식

16비트 워드의 상위 바이트와 하위 바이트를 서로 교환하는 switch_bytes 예로 호출 형식 차이를 보여준다.

3.1 태스크 호출

태스크 
switch_bytes(old_word, new_word);

입력 인수 old_word를 받고, 계산 결과를 출력 인수 new_word를 통해 외부로 전달한다.

3.2 함수 호출

함수 
new_word = switch_bytes(old_word);

입력 old_word를 함수에 전달하고, 함수 반환값을 할당문 우변의 값으로 받아 new_word에 저장한다.

함수 → 수식의 피연산자처럼 사용 → 하나의 반환값
태스크 → 독립된 절차 문장으로 호출 → output/inout으로 결과 전달

4. 7.2 함수

함수는 하나의 결과 값을 호출 위치로 돌려보내는 데 사용한다. 함수가 Verilog 수식 안에서 피연산자처럼 사용될 수 있다고 설명한다.

input arguments →
function
→ 1개의 반환값
조합회로 관점
함수 내부에는 시간 제어가 없으므로, 합성 가능한 함수는 입력 값으로부터 즉시 결과를 계산하는 조합논리 표현에 적합하다.

5. 7.2.1 함수의 정의

함수는 function으로 시작하여 endfunction으로 끝난다. 두 가지 정의 방법을 제시한다.

5.1 방법 ① — 입력 인수를 선언부에서 별도 선언

function [automatic] [range_or_type] function_name; input [range_or_type] port_name; ... block_item_declaration; procedural_statements; endfunction

5.2 방법 ② — 함수 이름 뒤 포트 목록에 입력 인수 선언

function [automatic] [range_or_type] function_name ( input [range_or_type] port_name, ... ); block_item_declaration; procedural_statements; endfunction

5.3 automatic

automatic은 각 함수 호출마다 별도의 저장 공간을 할당하도록 하여 재귀(recursive) 함수 호출을 허용하는 선택사항으로 설명된다.

함수 호출 1 → 자신의 저장 공간
재귀 함수 호출 2 → 별도의 저장 공간

5.4 range_or_type

함수 결과 또는 입력 인수의 비트 폭·부호·자료형을 지정한다. 다음 형태를 예로 든다.

signed [msb:lsb] reg [msb:lsb] integer real time realtime
생략 시
함수 결과 자료형/범위를 생략하면 기본 1비트 reg로 처리된다.

5.5 함수 인수와 반환값

  • 함수 인수는 모두 input이다.
  • 반드시 하나 이상의 입력 인수를 가져야 한다.
  • 함수 이름과 같은 이름의 임시 reg가 내부적으로 결과 저장 용도로 사용된다.
  • 함수 결과는 해당 함수 이름에 값을 할당하여 호출 위치로 반환한다.
함수 이름과 같은 별도 변수를 선언하면 안 됨
함수 이름 자체가 반환값을 담는 내부 변수 역할을 하기 때문이다.

5.6 getbyte 정의 예

예시 7-3 — 방법 ①
function [7:0] getbyte;

input [15:0] addr;
reg [15:0] temp;

begin
    // addressed word에서 low-order byte를 추출하는 코드
    getbyte = result_expression;
end

endfunction
예시 7-3 — 방법 ②
function [7:0] getbyte (
    input [15:0] addr
);

reg [15:0] temp;

begin
    // addressed word에서 low-order byte를 추출하는 코드
    getbyte = result_expression;
end

endfunction
addr[15:0] → getbyte() → 8비트 반환값

6. 7.2.2 함수의 호출

function_name ( expression1, expression2, ... )

함수는 할당문 우변에서 단독으로 사용할 수도 있고, 더 큰 수식의 한 피연산자로 사용할 수도 있다.

예시 7-4
word =
    control
    ? {getbyte(msb_byte), getbyte(lsb_byte)}
    : 0;

6.1 평가 흐름

control 참 → getbyte(msb_byte) + getbyte(lsb_byte) → 결합하여 word
함수 인수 평가 순서
함수 호출의 인수 평가 순서는 정의되지 않으므로, 인수 평가 순서에 의존하는 부수효과를 만들지 않는다.

7. 7.2.3 함수의 규칙

함수 사용을 제한하는 핵심 규칙들을 다음과 같이 정리한다.

  1. 시간 제어를 포함할 수 없다. #, @, wait 사용 불가
  2. 하나 이상의 input 인수가 필요하다.
  3. output, inout 인수를 가질 수 없다.
  4. 함수 이름과 같은 내부 반환 변수에 결과값을 할당해야 한다.
  5. nonblocking 할당을 가질 수 없다.
  6. 태스크를 호출할 수 없다.
함수 설계 체크
시간이 흐르는 동작이 필요한가? → 함수보다 태스크를 검토
출력이 여러 개인가? → 태스크 검토
즉시 하나의 계산값만 필요한가? → 함수에 적합

8. 함수 예제 — word_align

코드 7-1은 8비트 입력 word를 받아 최상위 비트(MSB)가 1이 되도록 왼쪽 시프트시키는 기능을 함수로 정의한다.

코드 7-1
module word_aligner (
    input  [7:0] word_in,
    output [7:0] word_out
);

function [7:0] word_align;

    input [7:0] word;

    reg [7:0] temp;
    integer i;

    begin
        temp = word;

        if (temp == 8'h00 || temp[7] == 1'b1)
            word_align = temp;

        else
            for (i = 7; i >= 0; i = i - 1) begin
                if (temp[7] == 0)
                    temp = temp << 1;
                else
                    word_align = temp;
            end
    end

endfunction

assign word_out = word_align(word_in);

endmodule

8.1 동작 흐름

word_in → temp = word → temp[7] 검사
MSB=0 → temp << 1 → 다시 MSB 검사
MSB=1 또는 입력=0 → word_align에 결과 저장 → word_out
회로 관점
이 함수는 클록을 사용하지 않는다. 따라서 입력 word_in에서 출력 word_out까지 시프트와 조건 판단이 조합논리 형태로 연결되는 계산으로 이해할 수 있다.

9. automatic 재귀 함수 — factorial

코드 7-2는 함수가 다른 함수뿐 아니라 자기 자신을 다시 호출하는 재귀 함수로도 정의될 수 있음을 보여준다. 이를 위해 automatic이 사용된다.

코드 7-2
module compute_factorial;

function automatic integer factorial;

    input [7:0] operand;

    if (operand >= 2)
        factorial =
            factorial(operand - 1) * operand;
    else
        factorial = 1;

endfunction

integer result;
integer n;

initial begin
    for (n = 0; n <= 7; n = n + 1) begin
        result = factorial(n);

        $display(
            "%0d factorial = %0d",
            n, result
        );
    end
end

endmodule

9.1 재귀 계산 예 — 4!

factorial(4) → factorial(3) × 4 → factorial(2) × 3 × 4
factorial(1)=1 → 2 → 6 → 24

10. 7.3 태스크

태스크는 함수보다 제약이 적고 여러 input/output/inout 인수를 사용할 수 있으며, 필요하면 지연과 이벤트 제어를 포함할 수 있다.

input / inout →
task
→ output / inout
함수보다 태스크가 필요한 대표 상황
여러 개의 결과가 필요하거나, 버스 요청/승인처럼 일정 조건을 기다려야 하거나, #, @, wait 같은 시간 흐름이 필요한 경우

11. 7.3.1 태스크의 정의

태스크는 task로 시작하여 endtask로 끝난다. 함수와 마찬가지로 두 가지 포트 선언 형식을 제시한다.

11.1 방법 ① — 포트 별도 선언

task [automatic] task_name; port_declaration port_name; ... block_item_declaration; procedural_statements; endtask

11.2 방법 ② — 태스크 이름 뒤에서 포트 선언

task [automatic] task_name ( input ..., output ..., inout ... ); block_item_declaration; procedural_statements; endtask

11.3 포트 방향

방향값의 흐름
input호출부 → 태스크 내부
output태스크 내부 → 호출부
inout양쪽 방향
automatic task
automatic 태스크가 호출될 때마다 저장 공간을 할당하여 이전 호출이 실행 중인 동안에도 다시 호출될 수 있는 재진입(reentrant) 구조를 지원한다고 설명한다.
함수와의 가장 큰 차이
태스크 내부에는 #, @, wait와 같은 시간 제어를 포함할 수 있다. 즉, “계산값”뿐 아니라 시간에 따른 절차를 묶을 수 있다.

12. 7.3.2 태스크 호출과 인수 전달

task_name ( expression1, expression2, ... );

태스크는 always, initial 또는 다른 태스크 안에서 독립된 하나의 문장으로 호출한다.

12.1 인수 순서

태스크 호출문의 인수는 태스크 정의에서 선언된 인수 순서와 1:1로 대응한다.

순서가 중요
함수처럼 이름 기반 연결이 아니라, 호출 괄호 안의 위치가 각 태스크 인수와 대응한다.

12.2 output / inout에서 사용할 수 있는 호출부 표현

  • reg, integer, real, realtime, time
  • 메모리 참조
  • variable의 결합(concatenation)
  • 메모리 참조의 결합
  • reg, integer, time의 비트 선택/부분 선택

12.3 값 전달 흐름

호출 시점
호출부의 input/inout 값이 태스크 내부 인수로 전달된다.
태스크 실행
태스크 내부 절차형 문장이 실행된다. 시간 제어가 있으면 호출 프로세스는 태스크가 끝날 때까지 기다릴 수 있다.
종료 시점
태스크의 output/inout 결과가 호출부의 대응 변수로 전달된다.
태스크 인수 전달
태스크 인수는 값 전달 방식으로 이해하며, input 값은 호출 시 전달되고 output/inout 결과는 태스크 종료 시 호출부로 반영된다.

13. 태스크 예제 — my_task

코드 7-3은 두 입력 a, b의 OR와 XOR를 동시에 계산해 두 개의 결과를 반환한다. 함수는 한 개의 반환값을 갖지만, 태스크는 이처럼 여러 output을 동시에 사용할 수 있다.

코드 7-3
module my_task_ex;

reg a, b;
reg aORb, aXORb;

task my_task (
    input  xa,
    input  xb,
    output OR,
    output XOR
);

begin
    OR  = xa | xb;
    XOR = xa ^ xb;
end

endtask

initial begin
    a = 1'b0;
    b = 1'b0;

    #10 a = 1'b1;
        b = 1'b1;

    #10 a = 1'b0;
        b = 1'b1;

    #10 a = 1'b1;
        b = 1'b0;

    #10 $finish;
end

always @(a, b)
    my_task(
        a,
        b,
        aORb,
        aXORb
    );

endmodule

13.1 호출 인수 매핑

태스크 인수호출부 신호방향
xaainput
xbbinput
ORaORboutput
XORaXORboutput

13.2 내부적으로 이해하면

a → xa + b → xb → OR / XOR 계산
OR → aORb , XOR → aXORb

14. 태스크 예제 — count_ones

코드 7-4는 8비트 입력 data_word 안에 포함된 논리 1의 개수를 세는 기능을 태스크로 구현한다.

코드 7-4
module bit_counter (
    input  [7:0] data_word,
    output [3:0] bit_count
);

reg [3:0] bit_count;

always @(data_word)
    count_ones(
        data_word,
        bit_count
    );

task count_ones;

    input  [7:0] reg_a;
    output [3:0] count;

    reg [3:0] count;
    reg [7:0] temp_reg;

    begin
        count = 0;
        temp_reg = reg_a;

        while (temp_reg) begin
            if (temp_reg[0])
                count = count + 1;

            temp_reg = temp_reg >> 1;
        end
    end

endtask

endmodule

14.1 알고리즘

temp_reg = data_word → LSB 검사 → 1이면 count+1
temp_reg >> 1 → 다음 비트를 LSB로 이동 → temp_reg가 0이 될 때까지 반복

14.2 예: 8'b1011_0101

단계temp_reg LSBcount
초기10 → 1

이 태스크 자체에는 클록이 없고 always @(data_word)에서 호출된다. 따라서 입력 변화에 대해 결과를 계산하는 행위수준 조합 계산 예로 이해할 수 있다.

15. 태스크 예제 — read_mem 메모리 읽기

코드 7-5는 함수로 구현하기 어려운 대표적인 태스크 사용 예다. 메모리 읽기 요청을 발생시키고, 승인 신호를 기다린 뒤, 주소 버스와 데이터 버스를 이용해 값을 받아오는 절차를 포함한다.

코드 7-5
task read_mem (
    input  [15:0] address,
    output [31:0] data
);

begin
    read_request = 1'b1;

    wait (read_grant)
        addr_bus = address;

    data = data_bus;

    #5 addr_bus = 16'bz;

    read_request = 1'b0;
end

endtask


always @(posedge clk) begin
    read_mem(
        PC,
        IR
    );
end

15.1 시간 순서

① read_request = 1
메모리 읽기 요청을 활성화한다.
② wait(read_grant)
메모리/버스 측에서 읽기 승인을 줄 때까지 기다린다.
③ addr_bus = address
승인 후 입력 인수 address를 주소 버스에 출력한다.
④ data = data_bus
데이터 버스 값을 태스크 output 인수 data에 저장한다.
⑤ #5 후 addr_bus = z
5 time unit 후 주소 버스를 high-impedance 상태로 해제한다.
⑥ read_request = 0
읽기 요청을 종료하고 태스크를 빠져나온다.

15.2 함수로 하기 어려운 이유

read_mem 동작함수 가능 여부
wait(read_grant)함수에서는 불가
#5함수에서는 불가
여러 외부 신호 제어태스크가 더 적합
output 인수 사용함수는 output 인수 불가
Simulation / RTL 합성 구분
이 예제에는 wait와 #5가 포함되어 있으므로, 핵심은 “태스크는 시간 제어를 포함할 수 있다”는 문법·시뮬레이션 모델링 특성이다. 실제 FPGA에서 메모리 버스 프로토콜을 구현할 때는 클록 기반 FSM(유한상태머신) 등 합성 가능한 순차제어 구조와 구분해 이해해야 한다.

15.3 호출 시점

posedge clk → read_mem(PC, IR) → 요청/승인/버스 읽기 절차 → IR에 결과 전달
