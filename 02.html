1. CHAPTER 02 개요

Verilog HDL(베릴로그 HDL, 하드웨어 기술 언어)은 일반적인 소프트웨어 프로그래밍 언어와 유사하게 자료형과 연산자를 제공하지만, 자료형은 단순히 “값을 담는 형식”만 의미하지 않는다. 신호가 어떤 방식으로 구동되고, 값이 어떻게 유지되며, 어떤 하드웨어 구조를 표현하는지와 직접 연결된다.

net 자료형

wire, tri, wand, wor 등

회로 소자와 모듈 사이의 연결을 모델링한다.

variable 자료형

reg, integer, real, time, realtime

always, initial 등의 절차형 할당에서 값을 받는다.

이 장핵심 관점
같은 “신호”처럼 보여도 wire와 reg는 값을 받는 방식과 의미가 다르다. Verilog 소스는 논리합성(logic synthesis, 로직 신서시스)을 통해 실제 회로로 변환되므로 자료형과 연산자를 코드 문법이 아니라 회로 구조와 연결해서 이해해야 한다.
그룹대표 자료형핵심 역할
netwire, tri, wand, wor ...회로 요소 사이의 물리적 연결
variablereg, integer, real, time, realtime절차형 블록에서 값을 할당받고 다음 할당까지 유지

2. 2.1.1 논리값

Verilog HDL은 디지털 회로를 표현하기 위해 0, 1, x, z의 4가지 논리값을 지원한다. 각 비트는 독립적으로 이 네 값 중 하나를 가질 수 있다.

0
논리 0
false(거짓)
접지/Low 상태
1
논리 1
true(참)
전원/High 상태
x
unknown
0인지 1인지
확정할 수 없음
z
high-impedance
구동자가 없는
고임피던스 상태

2.1 하드웨어적으로 무엇을 의미하는가

두 구동자가 서로 다른 값 → 충돌 → x
구동자가 없음 → 출력을 강제로 0/1로 만들지 않음 → z
설명
0과 1은 서로 논리적 보수 관계이다. 일반적인 논리 연산에서 z가 입력에 포함되면 대부분 x와 유사한 영향을 줄 수 있으나, MOS 스위치 모델에서는 예외적으로 z가 그대로 전달될 수 있다.

3. 2.1.2 net 자료형

net 자료형은 논리 게이트나 모듈과 같은 하드웨어 요소 사이의 물리적인 연결(physical connection)을 추상화한 자료형이다.

3.1 Verilog의 주요 net 자료형

자료형용도특징
wire일반 연결가장 기본적인 net. 별도 기능 없음
tri3상태 연결wire와 유사하나 z 상태를 포함하는 연결을 명확히 표현
wandwired-AND다중 구동자를 AND 방식으로 결합
worwired-OR다중 구동자를 OR 방식으로 결합
triand3상태 wired-ANDwand와 유사
trior3상태 wired-ORwor와 유사
supply0접지전원 모델링용 global net
supply1전원전원 모델링용 global net
tri0pull-down 연결구동이 없으면 0
tri1pull-up 연결구동이 없으면 1
trireg전하 저장 노드이전 구동 값을 유지하는 특수 net
net핵심
일반적인 net는 스스로 값을 저장하지 않는다. 게이트 프리미티브나 연속 할당문 등의 구동자(driver)가 만든 값이 net에 연속적으로 전달된다. 구동자가 없으면 일반 net의 기본값은 z이다.

3.2 net 선언 문법

net_type [signed] [range] [#(delay)] net_name [array] {, net_name [array]};
net_type [signed] [range] [#(delay)] net_name = continuous_assignment;
예시 2-1: net 자료형 선언
wire w1, w2;
wire [7:0] bus;
wire enable = 1'b0;
wand w3;
tri [15:0] busa;
선언의미
wire w1, w2;1비트 wire 두 개
wire [7:0] bus;8비트 wire 벡터
wire enable = 1'b0;선언과 함께 연속 할당되는 1비트 wire
wand w3;1비트 wired-AND net
tri [15:0] busa;16비트 tri net

3.3 wire와 tri

wire와 tri는 문법과 기본 기능이 유사하다. 둘의 구분을 하드웨어에서 3상태(tri-state, 트라이스테이트)를 명확히 나타내기 위한 표현상의 차이로 설명한다.

다중 구동자 충돌
같은 강도의 두 구동자가 같은 값을 내면 그 값으로 결정된다. 한쪽이 0이고 다른 쪽이 1이면 충돌하므로 결과는 x가 된다. z는 해당 구동자가 사실상 선로를 구동하지 않는 상태로 해석된다.

4. wired net — wand, wor, triand, trior

다중 구동자를 갖는 wired 논리를 모델링하기 위해 wand, wor, triand, trior가 제공된다.

wand / triand

wired-AND 구성

구동자 중 하나 이상이 0이면 결과는 0

wor / trior

wired-OR 구성

구동자 중 하나 이상이 1이면 결과는 1

기술적 배경
wired-AND는 open-collector 로직, wired-OR는 emitter-coupled 로직과 연계해서 설명되며, 최신 CMOS 구현에서는 이러한 물리적 구조가 일반적이지 않다고 언급한다.
코드 2-1: wire와 wand 자료형의 차이
module wand_ex;

reg a, b, c;

wire w_nor, w_buf, w_wire;
wand w_wand;

initial begin
    a = 0; b = 0; c = 0;
    #50 a = 1; b = 1;
end

nor (w_nor, a, b);
buf (w_buf, c);

nor (w_wire, a, b);
buf (w_wire, c);

nor (w_wand, a, b);
buf (w_wand, c);

endmodule

4.1 같은 다중 구동이라도 결과가 다르다

wire → 0과 1 충돌 → x
wand → wired-AND 규칙 적용 → 0 또는 1
시뮬레이션
w_wire와 w_wand가 동일한 두 구동자를 갖더라도 자료형의 결정 규칙 때문에 서로 다른 결과를 갖는 점을 보여준다.

5. trireg · tri0 · tri1 · supply0 · supply1

5.1 trireg

trireg는 물리적인 전하 저장 노드(charge storage node)를 모델링하기 위한 net이다. 일반 net와 달리 모든 구동자가 z가 되더라도 마지막 값을 유지할 수 있다.

상태조건동작
구동 상태(driven state) 하나 이상의 구동자가 0, 1, x를 출력 결정값이 trireg에 전달되어 현재 값이 됨
정전용량 상태(capacitive state) 모든 구동자가 z 마지막으로 구동된 값을 유지

5.2 tri0 / tri1

자료형구동자가 없을 때하드웨어 의미
tri00저항성 pull-down이 연결된 net
tri11저항성 pull-up이 연결된 net

5.3 supply0 / supply1

supply0와 supply1은 각각 접지와 전원 연결을 모델링하는 net이며, 이들이 supply 강도를 갖는다고 설명한다.

5.4 신호강도

net에서 charge strength와 drive strength를 설명하며, 특히 trireg의 charge strength를 small, medium, large로 지정할 수 있다고 설명한다.

예시 2-2: 신호강도 지정
trireg a;
trireg (large) #(0,0,50) cap1;
trireg (small) signed [3:0] cap2;
RTL 관점의 주의
신호강도가 대부분의 합성 툴에서 지원되지 않으므로 RTL 수준 모델링에는 사용하지 않는 것이 좋다고 설명한다. 즉, 이 부분은 주로 시뮬레이션 모델과 라이브러리 수준에서 이해하는 편이 적절하다.

6. 2.1.3 variable 자료형

Verilog HDL의 reg, integer, real, time, realtime은 variable 자료형에 속한다. variable절차형 할당문이 실행될 때 값이 바뀌며, 다음 할당이 일어날 때까지 그 값을 유지한다.

자료형기본 초기값핵심 용도
regx절차형 블록에서 비트/벡터 값 저장
integerx정수형 범용 변수
timex시뮬레이션 시간 저장
real0.0실수형 변수
realtime0.0실수 형태의 시간값

6.1 variable 선언 문법

variable_type [signed] [range] variable_name [array] {, variable_name [array]};
variable_type [signed] [range] variable_name = initial_value;
부호 해석
variable에는 음의 값을 넣을 수 있지만, 부호를 유지해서 해석하려면 signed reg, integer, real, realtime처럼 signed 성격을 갖는 자료형을 사용해야 한다. unsigned reg와 time을 unsigned 값으로 취급한다고 설명한다.

7. reg 자료형

reg는 always나 initial 블록 내부의 절차형 할당문에 의해 값을 받는 variable 자료형이다. 할당과 할당 사이에서 값을 유지한다.

예시 2-3: reg 선언
reg a;
reg [3:0] b;
reg signed [3:0] signed_reg;
reg [-1:4] c;
reg [4:0] x, y, z;
선언비트 폭 / 의미
reg a;1비트 reg
reg [3:0] b;4비트 reg
reg signed [3:0] signed_reg;4비트 signed, 범위 -8 ~ 7
reg [-1:4] c;6비트 reg
reg [4:0] x, y, z;각각 5비트 reg

7.1 reg라고 해서 모두 플립플롭은 아니다

이 부분을 매우 중요하게 설명한다. reg는 플립플롭이나 래치 같은 저장소자를 모델링할 때 사용할 수 있지만, 조합회로의 출력 변수에도 사용될 수 있다. 따라서 reg 선언 자체가 하드웨어 레지스터를 의미하지 않는다.

순차회로 예: D 플립플롭 
module dff (
    input  clk,
    input  d,
    output qout
);

reg qout;

always @(posedge clk) begin
    qout <= d;
end

endmodule

qout은 클록 상승에지에서 값을 저장하므로 실제 저장소자에 대응한다.

조합회로 예: 2:1 MUX 
module mux21_if (
    input  [1:0] a,
    input  [1:0] b,
    input        sel,
    output [1:0] out
);

reg [1:0] out;

always @(a or b or sel) begin
    if (sel == 1'b0)
        out = a;
    else
        out = b;
end

endmodule

out은 reg로 선언되지만 회로는 조합논리 멀티플렉서다.

회로 판단 기준
자료형 이름이 아니라 할당이 언제 일어나는지를 본다.
posedge clk에서 값이 저장되면 순차회로이고, 모든 입력 변화에 즉시 다시 계산되면 조합회로이다.

8. integer · real · time · realtime

8.1 integer

integer는 하드웨어 레지스터 자체를 표현하기보다 범용 정수 변수로 사용된다. signed reg처럼 취급되며 연산 결과가 2의 보수 형태가 된다고 설명한다.

8.2 time

time은 시뮬레이션 시간을 저장하거나 타이밍을 확인하는 데 사용되며, 주로 시스템 태스크 $time과 함께 사용된다. 64비트 unsigned reg와 유사하게 동작한다고 설명한다.

8.3 real / realtime

real실수값을 저장하며, realtime은 real과 동일하게 취급되어 상호 교환 가능하다고 설명한다. 다만 일부 연산은 real에 사용할 수 없으며, 비트 선택이나 부분 선택도 사용할 수 없다.

예시 2-4
integer a;
real float;
time last_change;
realtime rtime;
real 사용 제한
real 변수에 대해 edge 지시자를 사용할 수 없고, 비트 참조(bit select)나 부분 참조(part select)를 할 수 없다고 설명한다. 또한 실수값이 정수형으로 변환될 때 가장 가까운 정수로 반올림된다.

9. 2.1.4 벡터와 배열

9.1 벡터(vector)

범위가 없는 net 또는 reg는 기본적으로 1비트이다. 여러 비트 신호를 만들 때는 자료형 뒤가 아니라 변수 이름 앞에 비트 범위 [msb:lsb]를 지정한다.

data_type [msb:lsb] identifier;
예시 2-5: 벡터 선언
reg  [7:0]  rega;
wire [15:0] d_out;
선언의미
reg [7:0] rega;8비트 reg 벡터
wire [15:0] d_out;16비트 wire 벡터
벡터는 하나의 다비트 신호
예를 들어 reg [7:0] rega는 8개의 독립된 배열 원소가 아니라 8비트 폭을 가진 하나의 벡터이다. 따라서 단일 할당문으로 전체 값을 받을 수 있다.

9.2 배열(array)

배열은 특정 자료형의 원소들을 여러 개 묶는 구조이며, 변수 이름 뒤쪽에 주소 범위를 작성한다.

data_type identifier [Uaddr:Laddr];
data_type identifier [Uaddr1:Laddr1][Uaddr2:Laddr2];
data_type [msb:lsb] identifier [Uaddr:Laddr];

9.3 벡터와 배열의 위치 차이

reg [7:0] mem_A [0:255];
[7:0] → 각 원소의 비트 폭 = 8비트
[0:255] → 배열 원소 개수 = 256개
즉
reg [7:0] mem_A [0:255];는 8비트 워드 256개로 구성된 메모리 구조를 표현한다.

9.4 배열 선언 예

예시 2-6
reg [7:0] mem_A [0:255];
reg array_B [7:0][0:255];
wire w_array [7:0][5:0];
integer int_A [1:64];
time chng_hist [1:1000];
선언의미
reg [7:0] mem_A [0:255] 8비트 reg 256개로 구성된 1차원 메모리
reg array_B [7:0][0:255] 1비트 reg로 구성된 8 × 256 2차원 배열
wire w_array [7:0][5:0] 1비트 wire로 구성된 8 × 6 2차원 배열
integer int_A [1:64] integer 64개 배열
time chng_hist [1:1000] time 값 1,000개 배열

9.5 배열 전체와 원소 할당의 차이

예시 2-7
mem_A = 0;                  // 오류: 배열 전체에 단일 할당
array_B[1] = 0;             // 오류: 여러 배열 원소를 한 번에 할당
array_B[1][12:31] = 0;      // 오류: 배열 일부 원소 묶음 할당

mem_A[1] = 0;               // 가능: 두 번째 워드에 0 할당
array_B[1][0] = 0;          // 가능: 특정 원소 하나에 할당
int_A[4] = 33559;           // 가능
chng_hist[t_index] = $time; // 가능
벡터와 배열을 혼동하지 말 것
벡터는 하나의 다비트 객체라서 전체 할당이 가능하지만, Verilog 배열은 워드 단위 또는 개별 원소 단위로 접근한다.

9.6 메모리 선언 예

예시 2-8
reg [1:n] Reg_A;
reg Mem_A [1:n];

wire [7:0] Array_2D [0:255][0:255];
wire Array_3D [0:255][0:255][7:0];

assign Array_2D[14][1][3:0] = 4'b1100;
assign Array_2D[1][3][6]    = 1'b1;
핵심 비교
reg [1:n] Reg_A;는 n비트 벡터이고, reg Mem_A [1:n];는 1비트 원소 n개로 구성된 메모리다. 대괄호의 위치가 회로 데이터 구조의 의미를 바꾼다.

10. 2.1.5 parameter

parameter는 variable이나 net에 속하지 않는 상수값이다. 시뮬레이션 실행 중에는 값을 변경할 수 없지만, 모듈 parameter는 컴파일/인스턴스화 과정에서 값을 덮어써서 같은 RTL 구조를 여러 설정으로 재사용할 수 있다.

10.1 선언 형식

localparam [signed] [range] parameter_name = value;
localparam constant_type parameter_name = value;
parameter [signed] [range] parameter_name = value;
parameter constant_type parameter_name = value;

constant_type은 integer, time, real, realtime 중 하나이다.

14. 수식 안의 정수 해석

수식에 들어가는 정수는 크게 다음 세 형태로 표현된다.

  • unsized, unbased 정수: 12
  • unsized, based 정수: 'd12, 'sd12
  • sized, based 정수: 16'd12, 16'sd12

밑수 지정자가 없는 정수를 signed로, 밑수만 지정한 정수를 unsigned로, s가 함께 지정된 경우 signed로 해석하는 차이를 강조한다.

예시 2-10: 수식에서 정수형 수의 처리
integer IntA, IntB, IntC, IntD;

IntA = -12 / 4;
IntB = -'d12 / 4;
IntC = -'sd12 / 4;
IntD = -4'sd12 / 4;
수식결과핵심 이유
-12 / 4-3unsized, unbased 정수는 signed
-'d12 / 41073741821밑수만 지정되어 unsigned로 해석
-'sd12 / 4-3s가 있어 signed로 해석
-4'sd12 / 414비트 signed 1100은 -4이고, 앞의 단항 -가 적용되어 +4가 됨
중요
비트패턴이 같아도 signed/unsigned 해석이 달라지면 산술 결과가 크게 달라질 수 있다. RTL에서 상수 표기법은 단순한 문법 문제가 아니라 실제 연산 결과와 회로 동작에 직접 영향을 준다.

16. 2.2.2 관계 연산자

관계 연산자는 두 피연산자의 크기를 비교하며 결과는 1비트의 참(1) 또는 거짓(0)이다. 피연산자에 x나 z가 포함되면 결과는 x가 될 수 있다.

연산자의미
a < ba가 b보다 작다
a > ba가 b보다 크다
a <= ba가 b보다 작거나 같다
a >= ba가 b보다 크거나 같다
예시 2-12
// A = 9, B = 4
// D = 4'b1001, E = 4'b1100, F = 4'b1xxx

A <= B   // 0
A >  B   // 1
E >= D   // 1
E <  F   // x

5.1 signed 비교 조건

  • 두 피연산자가 모두 signed integer 계열이면 signed 값으로 비교한다.
  • 한쪽이 real이면 다른 쪽도 실수형으로 변환한 뒤 비교한다.
  • 그 외의 경우 unsigned 비교로 설명한다.

5.2 산술 연산자와의 우선순위

a < b - 1

// 명확하게 표현
a < (b - 1)
관계 연산자는 산술 연산자보다 우선순위가 낮으므로 산술 계산 후 비교가 이루어지는 형태가 일반적이다.

17. 2.2.3 등가 연산자

연산자의미x/z 포함 시
==같다결과가 x가 될 수 있음
!=같지 않다결과가 x가 될 수 있음
===case equalityx/z도 값으로 포함하여 비교
!==case inequalityx/z도 값으로 포함하여 비교
예시 2-14
// A = 9, B = 4
// D = 4'b1001, E = 4'b1100
// F = 4'b1xxz, G = 4'b1xxz, H = 4'b1xxx

RTL 합성 주의

20. 2.2.6 축약 연산자

축약 연산자는 하나의 벡터 피연산자 전체를 한 비트 결과로 줄인다. 즉, 벡터 내부의 여러 비트를 순차적으로 같은 연산으로 묶어 하나의 결과를 만든다.

예시 2-20: 4비트 parity
wire [3:0] cnt;
wire parity;

assign parity = ^cnt;

// 위 코드는 다음과 동일한 의미
assign parity = cnt[3] ^ cnt[2] ^ cnt[1] ^ cnt[0];

9.1 4입력 NAND 게이트

코드 2-3
module nand4_op1 (
    input  [3:0] a,
    output       y
);

assign y = ~(a[0] & a[1] & a[2] & a[3]);

endmodule


module nand4_op2 (
    input  [3:0] a,
    output       y
);

assign y = ~&a;

endmodule
두 코드는 같은 회로 의미
첫 번째는 비트 AND를 모두 풀어서 쓴 표현이고, 두 번째는 축약 NAND로 같은 기능을 짧게 표현한 것이다.

9.2 4비트 2입력 NOR

코드 2-4
module nor_op (
    input  [3:0] a,
    input  [3:0] b,
    output [3:0] y
);

assign y = ~(a | b);

endmodule

이 코드는 각 비트 위치마다 OR 후 NOT을 수행하므로, 4개의 2입력 NOR 게이트가 병렬로 존재하는 구조에 대응한다.

22. 2.2.8 조건 연산자

조건 연산자 ?:는 3개의 피연산자를 사용하는 3항 연산자이다.

sel ? a : b
sel 평가결과
참a 선택
거짓(0)b 선택
x 또는 za와 b를 비트별 비교하여 각 비트의 결과 결정
회로로 보면 MUX
sel ? a : b는 일반적으로 sel이 선택신호인 2:1 멀티플렉서 구조로 연결해 이해할 수 있다.

11.1 3상태 출력 버스 예

예시 2-22
wire [15:0] busa, data;

assign busa = drive_busa ? data : 16'bz;
drive_busa = 1 → busa = data
그 외 → busa = z

drive_busa가 x일 때 조건의 모호성 때문에 busa의 각 비트가 비교 규칙에 따라 결정된다고 설명한다.

23. 2.2.9 결합 및 반복 연산자

12.1 결합(concatenation) 연산자

중괄호 { } 안에 여러 피연산자를 나열하면 왼쪽부터 순서대로 비트를 이어 붙인다.

예시 2-23
wire [15:0] addr_bus;
wire [7:0] addr_h, addr_l;

assign addr_bus = {addr_h, addr_l};
addr_h[7:0] + addr_l[7:0] → addr_bus[15:0]
비트 폭
8비트 + 8비트를 결합하므로 결과는 16비트다. 결합 연산자는 각 피연산자의 크기를 알 수 있어야 하므로 unsized 상수의 사용을 허용하지 않는다고 설명한다.

12.2 결합 연산자를 좌변에 사용

예시 2-24
wire [3:0] a, b, sum;
wire carry;

assign {carry, sum} = a + b;
a[3:0] + b[3:0] → 5비트 결과 → {carry, sum[3:0]}
회로 구조
4비트 + 4비트 가산 결과의 최상위 비트를 carry로, 하위 4비트를 sum으로 분리하는 구조를 한 줄로 표현한다.

12.3 반복(replication) 연산자

{a{b}} 형식은 b를 a번 반복한다. 반복 횟수는 상수여야 한다.

예시 2-25
{4{w}}

// 위 표현은 다음과 동일
{w, w, w, w}
예시 2-26: 결합 + 반복
{4'b0011, {3{4'b0101}}}

// 결과
16'b0011_0101_0101_0101
4'b0011 + 4'b0101 × 3회 → 16비트
